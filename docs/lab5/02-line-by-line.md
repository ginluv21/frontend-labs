# Лабораторная работа 5: полный построчный разбор текущих исходников

Снимок кода: 27 октября 2026 года. Этот гайд объясняет именно текущие файлы проекта, а не начальный шаблон Vite и не прежнюю лабораторную 4. [Первый гайд](01-defense-guide.md) содержит требования, сценарий защиты и возможные вопросы преподавателя.

## Как устроен разбор

Для каждого файла сначала описано назначение. Далее идут небольшие блоки: зачем нужен блок, его точный исходный текст и объяснение каждой строки с настоящим номером в исходном файле. Номера не вставлены внутрь кода, чтобы фрагменты оставались пригодными для сравнения с редактором. Даже пустые строки и закрывающие скобки учтены. Строка исходника может содержать несколько CSS-свойств или выражений: объяснение раскрывает их все.

Здесь полностью приведён собственный исполняемый код, CSS и конфигурация проекта: 18 текстовых файлов. Не копируются исходники установленных библиотек, `node_modules`, результат `dist`, автоматически создаваемый lock-файл, локальные секреты и служебные материалы хостинга. README и сами учебные гайды являются документацией, а не дополнительными модулями приложения. Бинарный `public/owl-poses.png` не имеет строк программного кода; его роль объясняется в разделах Owl и CSS. В текущем проекте нет `jsconfig.json`, поэтому отсутствующий файл не выдумывается.

Некоторые файлы существовали в лабораторной 4. Они включены полностью, потому что без них нельзя объяснить запуск и работу текущей пятой лабораторной. Главные новые учебные механизмы находятся в `src/api`, `src/hooks/useAdvice.js`, обработчике формы и карточке результата.

## Карта чтения

Для понимания пользовательского сценария начни с `App.jsx`, затем `useAdvice.js`, `advice.js`, `client.js` и `AdviceResult.jsx`. Для запуска проекта полезно сначала прочитать package.json, index.html и main.jsx. Сервер и сборку изучай после клиентского пути: это другой контекст выполнения.

- Браузер исполняет React-код и Axios-клиент.
- Локальный Node запускает Vite и адаптер маршрута.
- На опубликованном сайте Worker выполняет общий серверный обработчик.
- Скрипт сборки выполняется до публикации и создаёт файл Worker; его шаблонная строка содержит код, который будет выполняться позднее.

Секретного значения API-ключа в этом гайде нет. Имя `GEMINI_API_KEY` является названием серверной переменной, а не самим ключом.

**Что делает блок и зачем:** Каждое правило относится к имени или пути. Оно помогает сохранить в репозитории исходники и не публиковать окружение. Уже отслеживаемые файлы от одного добавления правила не исчезают.

**Построчно:**

- **Строка 1.** `node_modules` исключает папку установленных npm-зависимостей. Её содержимое восстанавливают установкой пакетов, а не пишут руками.
- **Строка 2.** `dist/` исключает каталог результата сборки Vite и сгенерированного Worker. Слеш подчёркивает, что правило относится к каталогу.
- **Строка 3.** `package-lock.json` исключает автоматически создаваемый npm lock-файл по решению для этого учебного репозитория. Он фиксирует точные версии; в обычных проектах его часто сохраняют в Git для воспроизводимости.
- **Строка 4.** `.openai/` исключает служебную папку окружения публикации. Содержимое не относится к учебному React-коду.
- **Строка 5.** `.oxlintrc.json` исключает локальную конфигурацию линтера. Само наличие правила не означает, что этот файл обязательно существует.
- **Строка 6.** `AGENTS.md` исключает локальные инструкции помощнику. Правила проекта при этом продолжают действовать для работы в папке.
- **Строка 7.** `*.log` исключает файлы журналов с любым именем и расширением `.log`.
- **Строка 8.** `*.local` исключает локальные настройки с таким окончанием, включая файл окружения `.env.local`.
- **Строка 9.** `.vscode/` исключает локальную папку настроек редактора Visual Studio Code.
- **Строка 10.** `.idea/` исключает папку настроек IDE семейства JetBrains.
- **Строка 11.** `.DS_Store` исключает служебный файл метаданных папки, который может создавать macOS.
- **Строка 12.** `.env` исключает файл переменных окружения без дополнительного суффикса. Это важно, если в нём задаются секреты сервера.
- **Строка 13.** `.env.*` исключает варианты файлов окружения, например `.env.local` и `.env.production`. Игнорирование не делает уже опубликованный секрет безопасным.

### Строки 1-5. Сведения о пакете

**Что делает блок и зачем:** Описывают проект и режим JavaScript-модулей.

```json

```

**Построчно:**

- **Строка 1.** Открывается корневой JSON-объект. В JSON ключи и строки записываются в двойных кавычках.
- **Строка 2.** `name` задаёт имя пакета `frontend-labs`. Это не автоматически создаваемый адрес сайта и не название репозитория, хотя они могут совпадать.

- **Строка 4.** `version` хранит формальную версию пакета. Сейчас `0.0.0`; на сетевые запросы это поле не влияет.
- **Строка 5.** `type: module` означает использование ES-модулей в соответствующих `.js` файлах Node: `import` и `export` вместо CommonJS.

### Строки 6-11. Команды npm

**Что делает блок и зачем:** Позволяют запускать инструменты короткими командами npm run.

```json

  },
```

**Построчно:**

- **Строка 6.** Начинается объект `scripts`, где имя команды сопоставлено строке запуска.

- **Строка 8.** `build` сначала выполняет клиентскую сборку. Оператор оболочки `&&` запускает Node-скрипт упаковки сервера только при успешном завершении Vite.
- **Строка 9.** `lint` запускает oxlint для статической проверки. Это не отправка HTTP-запросов и не полный функциональный тест сайта.
- **Строка 10.** `preview` запускает локальный просмотр готовой сборки Vite. Наш плагин дополнительно подключает к нему серверный маршрут.

- **Строка 2.** Начинается HTML-документ. `lang="ru"` сообщает основной язык текста браузеру и вспомогательным технологиям.

- **Строка 7.** `title` определяет надпись во вкладке браузера. Это отдельная сущность от видимого `h1` внутри React.

```javascript
      ? 'Сова не дождалась ответа. Попробуй ещё раз.'

})
```

- **Строка 11.** В каждую карточку копируются id, заголовок и подпись источника. Функция загрузки в состоянии не хранится.
- **Строка 12.** Назначается статус `loading`, пустые данные и пустое сообщение ошибки. Это честное начальное ожидание автоматической загрузки.
- **Строка 13.** Закрываются объект карточки, `map`, функция инициализации и вызов `useState`.
- **Строка 14.** Пустая строка отделяет состояние от действия загрузки.

### Строки 15-19. Выбор и подготовка загрузки

**Что делает блок и зачем:** reload выбирает все источники или один id и сбрасывает только выбранные карточки.

```javascript
  const reload = useCallback(async (sourceId, signal, question = '') => {
    const selected = sources.filter(source => !sourceId || source.id === sourceId)
    setResults(previous => previous.map(result => selected.some(source => source.id === result.id)
      ? { ...result, status: 'loading', data: [], error: '' } : result))

```

**Построчно:**

- **Строка 15.** Создаётся стабильный асинхронный callback `reload(sourceId, signal, question)`. Вопрос по умолчанию пустой, остальные аргументы могут быть `undefined`.
- **Строка 16.** `filter` выбирает все источники при отсутствии id или только совпавший. Постоянные id служат адресацией отдельного повтора.
- **Строка 17.** Функциональный setter перебирает актуальные карточки. `some` проверяет, входит ли карточка в выбранные источники.
- **Строка 18.** Выбранная карточка копируется со статусом загрузки, пустыми data и error. Невыбранная возвращается без изменений: её результат сохраняется.
- **Строка 19.** Пустая строка отделяет подготовку UI от выполнения сетевых задач.

### Строки 20-32. Параллельные независимые задачи

**Что делает блок и зачем:** Каждая задача отдельно обрабатывает успех, пустоту, отмену и ошибку.

```javascript
    await Promise.all(selected.map(async source => {
      try {
        const data = await source.load(signal, question)
        if (signal?.aborted) return
        setResults(previous => previous.map(result => result.id === source.id
          ? { ...result, data, status: data.length ? 'success' : 'empty' } : result))
      } catch (error) {
        if (signal?.aborted) return
        setResults(previous => previous.map(result => result.id === source.id
          ? { ...result, status: 'error', error: error.message } : result))
      }
    }))
  }, [])
```

**Построчно:**

- **Строка 20.** `map` создаёт асинхронную задачу для каждого выбранного источника. `Promise.all` ожидает их совместно; задачи начинают выполняться без последовательного ожидания друг друга.
- **Строка 21.** В каждой задаче начинается собственный `try`. Это ключ к независимой обработке ошибок источников.
- **Строка 22.** Вызывается соответствующая функция загрузки с сигналом и вопросом. Канье использует только первый аргумент, сова оба. `await` получает нормализованный массив.
- **Строка 23.** Если сигнал уже отменён, результат не применяется. Optional chaining позволяет работать и без сигнала у ручных запросов.
- **Строка 24.** Функциональное обновление берёт свежий массив и ищет карточку завершившегося источника.
- **Строка 25.** В нужную карточку записываются данные и статус: непустой массив даёт `success`, пустой `empty`. Остальные карточки сохраняются.
- **Строка 26.** Начинается обработка исключения только этой задачи: сетевого сбоя или ошибки проверки JSON в API-функции.
- **Строка 27.** После отмены ошибка не отображается как неисправность. Это также защищает от результата отменённого первого запуска эффекта.
- **Строка 28.** Снова используется функциональное обновление свежего массива, чтобы не затереть параллельно пришедший ответ другого источника.
- **Строка 29.** В нужной карточке устанавливается `error` и сообщение из исключения. Старые данные уже очищены на этапе начала загрузки.
- **Строка 30.** Закрывается `catch` отдельного источника. Ошибка обработана внутри задачи и не обязана отклонять весь `Promise.all`.
- **Строка 31.** Закрываются callback `map`, сам `map` и ожидание `Promise.all`.
- **Строка 32.** Закрывается callback `reload`. Пустые зависимости допустимы здесь благодаря постоянному sources, стабильному setter и передаче меняющегося вопроса аргументом.

### Связать строки в одну картину

При первом рендере формируется массив карточек. После рендера эффект вызывает reload со своим сигналом. Reload сначала помечает выбранные карточки как loading, затем запускает задачи. API-функция возвращает массив: длина определяет success или empty. Исключение переводит только нужную карточку в error. Каждое обновление использует актуальный previous. Общий loading остаётся true, пока не завершились все загружаемые карточки.

При отправке формы путь тот же, но вопрос передаётся явно. При повторе указан sourceId, поэтому другая карточка сохраняется. Ни setResults, ни рендер сами по себе не запускают новый HTTP: нужен вызов reload. Стабильная ссылка reload позволяет эффекту не реагировать на каждое изменение results.

Не путай три массива: sources хранит описание источников; results хранит состояние карточек; result.data хранит нормализованные тексты одной карточки. Map может строить любой из этих новых массивов в зависимости от места вызова.

### Строки 9-15. Обработчик и ранние проверки

**Что делает блок и зачем:** Создаёт JSON-ответы и проверяет метод, ключ и происхождение.

```javascript
export async function handleOwl(request, env) {
  const reply = (data, status = 200) => Response.json(data, { status, headers: { 'Cache-Control': 'no-store' } })
  if (request.method !== 'POST') return reply({ error: 'Нужен POST-запрос.' }, 405)
  if (!env.GEMINI_API_KEY) return reply({ error: 'Сова пока не готова отвечать. Загляни чуть позже.' }, 503)
  const origin = request.headers.get('Origin')
  if (origin && origin !== new URL(request.url).origin) return reply({ error: 'Запрос с другого сайта отклонён.' }, 403)

```

**Построчно:**

- **Строка 9.** Экспортируется асинхронный handleOwl с Web Request и объектом окружения env. Возвращаемый Promise разрешается в Response.
- **Строка 10.** Локальная функция reply создаёт JSON Response со статусом по умолчанию 200 и Cache-Control:no-store. Параметр status можно переопределить для ошибки.
- **Строка 11.** Если метод не POST, сразу возвращается JSON с 405. Дальнейшие проверки и внешний запрос не выполняются.
- **Строка 12.** При отсутствии секретного ключа возвращается 503 и сообщение о временной неготовности. Значение ключа нигде не подставляется в текст ошибки.
- **Строка 13.** Из входящих заголовков читается Origin. Значение может отсутствовать, поэтому проверка ниже условная.
- **Строка 14.** Если присутствующий Origin отличается от origin самого URL, возвращается 403. Сравниваются схема, хост и порт; это не полноценная аутентификация запросов.
- **Строка 15.** Пустая строка отделяет ранние проверки от блока обработки тела.

**Что делает блок и зачем:** Обрабатывает HTTP-ошибки и нормализует итоговый текст.

```javascript

      ? 'Сова выдохлась. Дай ей передохнуть и попробуй снова.'
      : 'Мысль запуталась в скакалке. Попробуй ещё раз.' }, response.status === 429 ? 429 : 502)

    const parts = data.candidates?.[0]?.content?.parts || []
    const advice = parts.filter(part => !part.thought).map(part => part.text || '').join('').trim()
```

- **Строка 38.** Для 429 выбирается сообщение о необходимости передохнуть: источник ограничил частоту или квоту.
- **Строка 39.** Для других неуспешных статусов выбирается общая ошибка. Наружу отдаётся 429 при исходном 429, иначе 502, а не произвольное техническое тело поставщика.
- **Строка 40.** Успешное тело внешнего ответа разбирается методом response.json(). Ошибка разбора попадёт в общий catch.
- **Строка 41.** Из первого кандидата берутся content.parts с optional chaining. При отсутствии ожидаемого пути используется пустой массив.
- **Строка 42.** Части с truthy thought исключаются; из остальных берётся text или пустая строка, затем join соединяет без разделителя и trim удаляет краевые пробелы.
- **Строка 43.** В advice заменяются символы из диапазона Unicode 2010-2015 и минус 2212 на обычный дефис. Флаг g применяет замену ко всем вхождениям; reply возвращает JSON с итоговым advice.

- **Строка 47.** Любое оставшееся исключение даёт 504 с понятной фразой. Это общее сообщение, оно не доказывает, что причиной всегда было только долгое ожидание.
- **Строка 48.** Закрывается catch.
- **Строка 49.** Закрывается функция handleOwl. Внешнее окружение само отправит полученный Response клиенту.

### Граница сервера и браузера

Этот файл не импортируется в React-компоненты. Браузер получает только итоговый JSON через /api/owl. Серверный fetch не проходит через браузерный Axios interceptor, и это не нарушает устройство общего клиента React. На защите нужно назвать два уровня HTTP отдельно.

Проверки и понятные сообщения делают сценарий предсказуемым, но не превращают учебный обработчик в систему авторизации и защиты от злоупотреблений. Отсутствующий Origin разрешён этой проверкой; лимит строки применяется после чтения; инструкция модели не является формальной гарантией числа предложений. Эти ограничения важно понимать, а не заучивать неверные обещания.

**Построчно:**

### Строки 6-18. Среда и чтение локального запроса

**Что делает блок и зачем:** Читает переменные окружения и добавляет middleware для /api/owl.

```javascript
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '')
  const configureServer = server => {
    server.middlewares.use('/api/owl', async (req, res) => {
      let body = ''
      for await (const chunk of req) {
        body += chunk
        if (body.length > 2000) {
          res.writeHead(400, { 'Content-Type': 'application/json' })
          res.end(JSON.stringify({ error: 'Вопрос слишком длинный.' }))
          return
        }
      }
```

**Построчно:**

- **Строка 6.** DefineConfig получает функцию с текущим mode. Это позволяет читать переменные соответствующего режима, например development.
- **Строка 7.** LoadEnv читает файлы окружения относительно рабочей папки. Пустой префикс разрешает серверной конфигурации читать все имена; это само по себе не публикует их в React.
- **Строка 8.** Создаётся функция настройки сервера Vite. Это API плагинов сборщика, а не React-хук.
- **Строка 9.** К middleware-серверу подключается обработчик пути /api/owl. Callback асинхронный и получает Node req и res.
- **Строка 10.** Создаётся пустая строка для накопления текстового тела локального запроса.
- **Строка 11.** For await читает асинхронный поток входящих чанков. Тело может прибывать несколькими частями, а не одной строкой сразу.
- **Строка 12.** Очередной chunk добавляется к body. При строковой конкатенации буфер преобразуется в строковое представление.
- **Строка 13.** Если накопленная длина превысила 2000, начинается ранний отказ. Это длина накопленной строки, не точный лимит сырых сетевых байтов.
- **Строка 14.** В Node response записывается статус 400 и JSON Content-Type.
- **Строка 15.** Ответ завершается сериализованным объектом ошибки. End отправляет содержимое клиенту.
- **Строка 16.** Return прекращает локальный обработчик, не вызывая внешний API после превышения ограничения.
- **Строка 17.** Закрывается проверка размера.
- **Строка 18.** Закрывается цикл чтения чанков. Теперь полное допустимое body доступно далее.

### Строки 19-27. Преобразование Request и Response

**Что делает блок и зачем:** Переводит запрос Node в Web Request, затем обратно записывает ответ в Node response.

```javascript
      const request = new Request(`http://${req.headers.host}/api/owl`, {
        method: req.method, headers: req.headers,
        body: req.method === 'POST' ? body : undefined,
      })
      const response = await handleOwl(request, env)
      res.writeHead(response.status, Object.fromEntries(response.headers))
      res.end(await response.text())
    })
  }
```

**Построчно:**

- **Строка 19.** Создаётся Web Request для общего обработчика. Локальный URL собирается из Host и маршрута, чтобы handleOwl мог работать со стандартным request.url.
- **Строка 20.** В Web Request переносятся метод и заголовки входящего Node-запроса.
- **Строка 21.** Тело передаётся только для POST. При других методах body отсутствует, а handleOwl сам вернёт 405.
- **Строка 22.** Закрываются объект параметров и создание Request.
- **Строка 23.** Общий серверный обработчик вызывается с подготовленным Request и прочитанным env. Await получает Web Response.
- **Строка 24.** Статус и заголовки Web Response переводятся в Node response. Object.fromEntries превращает пары заголовков в обычный объект.
- **Строка 25.** Тело Web Response читается как текст и завершает Node-ответ. Клиент получает JSON, созданный handleOwl.
- **Строка 26.** Закрываются callback middleware и его регистрация.
- **Строка 27.** Закрывается функция configureServer.

## 18. `scripts/build-server.mjs`

Node-скрипт после клиентской сборки. Создаёт Worker, включающий серверный обработчик и статические файлы. Этот скрипт не нужно путать с кодом React.

### Строки 1-5. Инструменты и таблицы

**Что делает блок и зачем:** Подключают асинхронные операции файловой системы и задают MIME-типы.

```javascript
import { readFile, readdir, mkdir, writeFile } from 'node:fs/promises'

const assets = {}
const types = { '.html': 'text/html; charset=utf-8', '.js': 'text/javascript; charset=utf-8', '.css': 'text/css; charset=utf-8', '.png': 'image/png' }

```

**Построчно:**

- **Строка 1.** Из встроенного Node-модуля импортируются Promise-версии чтения файла, чтения каталога, создания папки и записи файла.
- **Строка 2.** Пустая строка отделяет импорт от данных сборки.
- **Строка 3.** Создаётся пустой объект assets. Во время сборки он станет таблицей URL-путей к MIME-типу и base64-содержимому файлов.
- **Строка 4.** Объект types сопоставляет расширения html, js, css и png с Content-Type. Для текстовых форматов указывается UTF-8.

### Строки 6-14. Сбор статических файлов

**Что делает блок и зачем:** Рекурсивно читает dist и кодирует байты в base64.

```javascript
async function collect(directory) {
  for (const entry of await readdir(directory, { withFileTypes: true })) {
    if (entry.name === 'server' || entry.name === '.openai') continue
    const path = `${directory}/${entry.name}`
    if (entry.isDirectory()) await collect(path)
    else assets[path.slice(4)] = { type: types[path.slice(path.lastIndexOf('.'))] || 'application/octet-stream', body: (await readFile(path)).toString('base64') }
  }
}

```

**Построчно:**

- **Строка 6.** Объявляется асинхронная функция collect, принимающая путь каталога.
- **Строка 7.** Readdir с withFileTypes возвращает записи с информацией о типе. For of последовательно обходит эти записи; await ожидает чтение списка.
- **Строка 8.** Пропускаются папки или записи с именами server и .openai, чтобы не включать серверный результат и служебные материалы в статику.
- **Строка 9.** Шаблонная строка собирает путь к текущей записи из каталога и имени.
- **Строка 10.** Если запись является каталогом, collect рекурсивно обходит его и ожидает завершения.
- **Строка 11.** Для файла ключ path.slice(4) удаляет префикс dist и сохраняет начальный слеш URL. Расширение находится через lastIndexOf; MIME берётся из types или fallback. ReadFile получает байты, toString(base64) кодирует их для хранения в строке.
- **Строка 12.** Закрывается цикл обхода записей.
- **Строка 13.** Закрывается рекурсивная функция collect.
- **Строка 14.** Пустая строка отделяет объявление функции от фактического запуска сборки.

### Строки 15-18. Начало генерации Worker

**Что делает блок и зачем:** Соединяет код handleOwl и таблицу ресурсов в одну строку будущей программы.

```javascript
await collect('dist')
const handler = await readFile('server/owl.js', 'utf8')
const worker = `${handler}
const assets = ${JSON.stringify(assets)};
```

**Построчно:**

- **Строка 15.** Collect вызывается для dist после Vite build. Top-level await разрешён в ES-модуле .mjs и ждёт полного сбора ресурсов.
- **Строка 16.** Исходный server/owl.js читается как UTF-8-текст. Его код будет включён в будущий Worker без отдельного импорта на хостинге.
- **Строка 17.** Открывается многострочная шаблонная строка worker. Подстановка handler вставляет прочитанный серверный код уже во время сборки.
- **Строка 18.** В текст будущей программы вставляется JSON-сериализация таблицы assets. Здесь подстановка выполняется в Node при сборке; получившийся объект будет доступен Worker позднее.

### Строки 19-28. Код, который будет работать на хостинге

**Что делает блок и зачем:** Содержимое шаблонной строки станет JavaScript-обработчиком Worker после сборки.

```javascript
export default {
  async fetch(request, env) {
    const path = new URL(request.url).pathname;
    if (path === '/api/owl') return handleOwl(request, env);
    const asset = assets[path === '/' ? '/index.html' : path];
    if (!asset) return new Response('Не найдено', { status: 404 });
    const body = request.method === 'HEAD' ? null : Uint8Array.from(atob(asset.body), char => char.charCodeAt(0));
    return new Response(body, { headers: { 'Content-Type': asset.type, 'Cache-Control': 'no-cache' } });
  }
};`
```

**Построчно:**

- **Строка 19.** Внутри генерируемого кода начинается default-экспорт объекта Worker. Пока это часть строки Node, а не уже выполняемый обработчик.
- **Строка 20.** В будущем Worker объявляется асинхронный метод fetch с входящим Request и серверным env. Имя fetch здесь обозначает обработчик платформы, не обращение к внешней модели само по себе.
- **Строка 21.** Из URL входящего запроса берётся pathname. Параметры query не входят в путь, поэтому /?v=8 по-прежнему соответствует /.
- **Строка 22.** Для точного пути /api/owl вызывается общий handleOwl. Возвращаемый Promise допустим внутри async-обработчика, платформа дождётся Response.
- **Строка 23.** Для корня выбирается /index.html, для остальных адресов ресурс ищется по исходному пути. Это простая таблица статики, не React Router.
- **Строка 24.** Если ресурс не найден, возвращается обычный Response с 404. Автоматической подстановки index.html для всех неизвестных путей нет.
- **Строка 25.** HEAD возвращает пустое тело; иначе base64 декодируется через atob, затем Uint8Array.from переводит символы двоичной строки в байты. Base64 не является шифрованием.
- **Строка 26.** Статический ресурс возвращается с сохранённым Content-Type и Cache-Control:no-cache. No-cache требует проверки актуальности, а не означает то же самое, что no-store.
- **Строка 27.** Закрывается метод fetch будущего Worker.
- **Строка 28.** Закрывается экспортируемый объект Worker, затем обратная кавычка завершает шаблонную строку worker. Всё между началом строки и этой точкой станет содержимым выходного JS-файла.

### Строки 29-31. Запись результата

**Построчно:**

- **Строка 30.** В dist/server/index.js записывается готовая строка Worker. Это сгенерированный результат сборки, его не нужно вручную редактировать или добавлять в Git.
- **Строка 31.** В терминал выводится подтверждение окончания сборки. Эта строка не публикует сайт и не доказывает успешный реальный ответ внешнего API.

## Как проверить, что ты понял весь путь

Возьми строку отправки в App и пройди по вызовам вручную. Найди параметры reload, затем source.load, затем http.post и конфигурацию instance. Для совы продолжи путь в handleOwl, найди извлечение advice и вернись к getOwl. Затем найди setResults и условие вывода в AdviceResult. Повтори путь с пустым массивом и с исключением.

Отдельно проследи путь запуска: HTML-контейнер -> main.jsx -> App. Затем путь сборки: команда package.json -> Vite -> collect(dist) -> генерация Worker -> запись dist/server/index.js. Нельзя заменять эти разные процессы одной фразой "React запускает сервер".

После изменения исходников номера и текст этого снимка могут устареть. Перед защитой сравни открытые файлы с соответствующими блоками. Полнота здесь относится к перечисленным файлам текущего снимка, а не к будущим изменениям или внутреннему коду библиотек.
