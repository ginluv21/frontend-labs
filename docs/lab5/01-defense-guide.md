## 1. Что нужно понять до заучивания терминов

Главная тема лабораторной - работа с API в React. Преподавателю нужно показать, что данные действительно приходят по сети, сохраняются в состоянии и меняют интерфейс. Мемная сова - тема приложения. Анимации и длинный дисклеймер - оформление. Они не заменяют демонстрацию запросов, загрузки, ошибки, повтора и пустого результата.

В приложении два источника:

1. Сова отвечает по смыслу вопроса. React отправляет вопрос нашему серверному маршруту, тот обращается к Gemini и возвращает ответ на русском.
2. Канье возвращает случайную цитату из публичного API `kanye.rest`. Вопрос пользователя на эту цитату не влияет.

Монетки в текущем коде нет. Advice Slip тоже больше не используется: его заменила сова с осмысленным ответом. Не описывай на защите предыдущий вариант проекта.

В пользовательском интерфейсе техническое название модели скрыто ради образа персонажа. На защите устройство объясняется прямо: текст совы генерируется внешним API, а не написан заранее и не появляется из локального массива.

### Если запомнить только одну последовательность

```text
Действие пользователя или открытие страницы
-> useAdvice запускает запрос
-> API-функция использует общий Axios-клиент
-> приходит ответ или ошибка
-> setResults обновляет состояние
-> React заново вызывает компоненты
-> карточка показывает новое состояние
```

Сеть получает данные. Хук управляет состоянием. Компоненты показывают это состояние. Если можешь без подсказки объяснить эти три предложения на примере одного запроса, основа уже понятна.

## 3. Соответствие требованиям лабораторной

Основа - предоставленное задание «Лабораторная работа 5. Работа с API в React». Условия на 5 включают условия на 3 и 4.

| Кнопка временно недоступна | `AdviceForm.jsx`, `Button.jsx` | `disabled={loading}` доходит до настоящего HTML-элемента `button` |
| Загрузка при открытии | `useAdvice.js` | `useEffect` вызывает `reload` |
| Осмысленные зависимости эффекта | `useAdvice.js` | `[reload]`, а ссылка на `reload` сохраняется через `useCallback` |

| Общий HTTP-клиент | `src/api/client.js` | Один `axios.create`, общие заголовки и тайм-аут |

## 4. Как устроен проект по слоям

### 4.1. Интерфейс

`src/App.jsx` соединяет приложение. Он хранит черновик вопроса, ошибку формы и последний отправленный вопрос. Сам HTTP-запрос в нём не написан: он вызывает `reload` из собственного хука.

`AdviceForm` получает данные и обработчики через props. Пользователь печатает в `textarea`, обработчик передаёт новое значение родителю. Кнопка отправляет форму.

`AdviceResult` получает одну запись источника и решает, что показывать: ожидание, ошибку, пустой результат или ответ. Внутри него небольшой компонент `AdviceText` выводит текст в `blockquote`.

`Owl` отвечает за изображение и реплики ожидания. Он не обращается к API, не выбирает модель и не задерживает получение результата. `Disclaimer` выводит статический текст. `Button` - общая кнопка, не привязанная к сове.

### 4.2. Состояние и управление запросами

`useAdvice` - собственный хук. Он знает, какие источники есть, как вызвать их функции и какое состояние у каждого источника. Компоненты используют его результат, не повторяя логику запросов.

Один источник может уже показать ответ, пока другой ещё загружается. Если запрос совы упал, цитата Канье не исчезает. Это следствие отдельных записей состояния, а не двух отдельных приложений.

### 4.3. API-модуль

В `src/api/advice.js` находятся `getOwl` и `getKanye`. Они отправляют запросы и приводят разные форматы ответа к общему виду:

```json
[
  {
    "id": "owl",
    "text": "Текст ответа"
  }
]
```

Сервер совы возвращает поле `advice`, а API Канье - поле `quote`. Компонентам не нужно помнить эту разницу. Они получают `text`.

### 4.4. HTTP-клиент

`src/api/client.js` создаёт один Axios instance. Это объект с заранее заданными настройками запросов: базовый адрес, заголовок `Accept`, тайм-аут, интерсепторы.

Оба запроса React идут через этот объект. У запроса Канье меняется `baseURL`, потому что это другой сайт, но общий клиент остаётся тем же.

### 4.5. Сервер совы

`server/owl.js` принимает веб-объект `Request` и возвращает `Response`. Он проверяет входящий вопрос, добавляет инструкцию персонажа, обращается к Gemini и возвращает только текст ответа или понятную ошибку.

Сервер нужен из-за секретного ключа. Если положить ключ в React, он попадёт в скачиваемый браузером код или запросы и перестанет быть секретом. Здесь браузер обращается к своему `/api/owl`, а запрос с ключом выполняется на сервере.

Не называй сервер «Express-приложением»: Express в зависимостях нет. Локально обработчик подключён к серверу Vite, работающему в Node.js. На хостинге тот же обработчик включён в Worker. Это разные среды запуска, использующие общие веб-интерфейсы `Request`, `Response` и `fetch`.

### 4.6. Сборка и оформление

`vite.config.js` настраивает React, алиас `@` и локальный маршрут совы. `scripts/build-server.mjs` упаковывает результат Vite для хостинга. CSS определяет ретро-оформление, адаптивность и анимации.

Генерируемый `dist/server/index.js` получается автоматически. Его не нужно писать вручную и не нужно разбирать как исходник из миллионов символов: исходная логика полностью находится в небольшом build-скрипте и `server/owl.js`.

## 5. Две полные цепочки данных

### 5.1. Сова

```text
textarea
-> question в App
-> handleSubmit
-> reload(undefined, undefined, question.trim())
-> getOwl(signal, question)
-> общий http.post('/api/owl', { question }, { signal })
-> сервер handleOwl
-> запрос к Gemini с секретным ключом и инструкцией персонажа
-> JSON { advice: "..." }
-> getOwl возвращает [{ id: 'owl', text: '...' }]
-> setResults
-> AdviceResult
-> result.data.map
-> AdviceText
-> blockquote на странице
```

Слово `undefined` здесь не ошибка. Первое пропущенное значение означает «не ограничивать загрузку одним источником». Второе означает «для этого ручного вызова не передан внешний сигнал отмены». Третий аргумент - сам вопрос.

### 5.2. Канье

```text
reload
-> getKanye
-> тот же http.get с baseURL https://api.kanye.rest
-> JSON { quote: "..." }
-> getKanye возвращает [{ id: 'kanye', text: '...' }]
-> setResults
-> AdviceResult
-> AdviceText
```

Канье не получает вопрос пользователя. `reload` передаёт одинаковый набор аргументов всем функциям источников, но `getKanye` использует только первый аргумент `signal`. Лишний аргумент JavaScript-функции сам по себе не мешает её вызову.

### 5.3. Что именно хранится в состоянии

Пример одной записи `results` после успеха:

```json
{
  "id": "owl",
  "title": "Ответ совы",
  "method": "Мудрость на высоте одного прыжка.",
  "status": "success",
  "data": [
    { "id": "owl", "text": "Вжих-вжих! Начни с маленькой задачи." }
  ],
  "error": ""
}
```

Внешний `id` определяет источник и карточку. Внутренний `id` определяет элемент ответа в массиве `data`. Сейчас каждый источник возвращает не больше одного текста, поэтому постоянный ключ слота подходит.

`results.length` обычно равен двум: это количество источников. `results[0].data.length` может быть нулём или единицей: это количество полученных текстов этого источника. Не путай эти два массива.

## 6. Сценарий при первом открытии

1. Загружается `index.html` с пустым контейнером `root`.
2. Браузер запускает `src/main.jsx`.
3. `createRoot` подключает React к контейнеру, затем рендерит `App`.
4. `App` вызывает `useAdvice` на верхнем уровне.
5. Ленивый инициализатор `useState` создаёт две записи со статусом `loading` и пустыми массивами данных.
6. На первом экране уже виден статус ожидания. Кнопка формы недоступна.
7. После отображения компонента эффект создаёт `AbortController` и вызывает `reload`.
8. `reload` выбирает оба источника и отмечает их как загружающиеся.
9. Две асинхронные функции начинают выполняться параллельно.
10. Перехватчик Axios выводит метод и адрес каждого запроса.
11. Канье может ответить раньше совы. Его запись становится `success`, хотя другая ещё `loading`.
12. После ответа совы её запись тоже обновляется. Если ответа нет, записывается `empty` или `error`, в зависимости от причины.
13. `loading` вычисляется через `some`: он остаётся истинным, пока хотя бы один источник загружается.
14. Когда загрузок не осталось, кнопка снова доступна, таймер совы очищается, прыжки прекращаются.

При первом запросе вопрос пустой. Это допустимый внутренний сценарий: сервер подставляет просьбу дать общий бодрый совет посетителю. Это не случайно пропущенная проверка формы. Форма не позволяет вручную отправить пустой вопрос, а автоматическая первоначальная загрузка использует общий совет.

## 7. Сценарий отправки вопроса

Пользователь вводит: «Не могу начать делать домашку по программированию».

`textarea` является управляемым полем. Его `value` берётся из `question`, а `onChange` вызывает переданную функцию `setQuestion`. Поэтому источником значения является состояние React.

Когда пользователь отправляет форму:

1. `handleSubmit` получает объект события.
2. `event.preventDefault()` останавливает обычную HTML-отправку, которая перезагрузила бы страницу.
3. Если уже идёт загрузка, обработчик заканчивается.
4. `trim()` удаляет пробелы по краям. Пустая строка вызывает текстовую ошибку и завершает обработчик до запроса.
5. При корректном вопросе ошибка очищается.
6. В `submittedQuestion` сохраняется отправленный текст.
7. Этот же текст напрямую передаётся третьим аргументом `reload`.
8. Хук очищает старые данные выбранных источников и переводит их в `loading`.
9. Кнопка блокируется; компонент совы начинает менять позы и реплики.
10. Запросы завершаются независимо, и каждый обновляет только свою запись.

Почему после `setSubmittedQuestion` передаётся `question.trim()`, а не сразу читается `submittedQuestion`? Setter запрашивает обновление следующего рендера. В текущем вызове обработчика переменная `submittedQuestion` всё ещё относится к предыдущему рендеру. Прямая передача подготовленного текста исключает чтение старого значения.

## 8. Повтор запроса и независимость карточек

Представь, что цитата Канье пришла, а запрос совы завершился ошибкой. В состоянии находятся две разные записи:

```text
owl: error, data: [], error: 'Понятное сообщение'
kanye: success, data: [{ id: 'kanye', text: '...' }]
```

Кнопка «Повторить» в карточке совы вызывает:

```javascript
reload(result.id, undefined, submittedQuestion)
```

`result.id` равен `owl`. Фильтр в хуке выбирает только этого источника. При обновлении массива запись Канье возвращается без изменений. Новый запрос цитаты не отправляется.

`submittedQuestion` нужен именно для этого. Если пользователь после ошибки напечатал новый черновик, но ещё не отправлял его, повтор всё равно должен относиться к прежнему вопросу. Поле `question` и сохранённый `submittedQuestion` решают разные задачи.

### Почему `Promise.all` не ломает независимость

`Promise.all` действительно обычно отклоняется, если один из переданных Promise отклонён. Но в данном коде каждый источник уже окружён собственным `try/catch` внутри `map`. Ошибка превращается в обновление соответствующей записи состояния и не выбрасывается дальше. Поэтому остальные функции продолжают выполняться.

Неправильно говорить: «`Promise.all` сам автоматически сохраняет успешные результаты при ошибках». Независимость обеспечивает наш внутренний `try/catch` и отдельное обновление каждого источника.

## 9. Состояния: загрузка, успех, пустота и ошибка

| Статус | Что он означает | Что видит пользователь |
| --- | --- | --- |
| `loading` | Запрос ещё не завершён | Ожидание и анимацию совы |
| `success` | Пришёл непустой нормализованный список | Текст ответа |
| `empty` | Запрос успешный, но список ответов пуст | Сообщение, что советов нет |
| `error` | Запрос или обработка ответа завершились исключением | Сообщение ошибки и кнопку повтора |

Ошибка и пустота - разные случаи. Например, HTTP 200 с `[]` является успешным пустым результатом. Отключённый интернет - ошибка. Объект без ожидаемого текстового поля - тоже ошибка формата, а не доказательство, что результатов нет.

В API-функциях намеренно предусмотрены `null`, пустой массив и пустой текст. Непустой массив неожиданной структуры не превращается молча в успех. Отсутствие нужного строкового поля вызывает `throw new Error(...)`.

Ошибки совы оформлены в образе персонажа. Фраза про запутавшуюся скакалку является сообщением о сбое, а не выдуманным ответом модели. После ошибки в `data` нет подставленного совета.

## 10. Короткая речь для начала защиты

Можно сказать своими словами:

> Я продолжаю приложение из четвёртой лабораторной. Это сайт совы, которая отвечает на вопрос пользователя. В пятой работе подключены реальные API. Ответ совы приходит через мой серверный маршрут, который обращается к внешней модели, а случайная цитата Канье загружается напрямую из публичного API. Все запросы React идут через один настроенный экземпляр Axios. Управление загрузкой вынесено в собственный хук `useAdvice`. Он хранит данные и статусы в `useState`, автоматически запускает загрузку через `useEffect` и возвращает функцию `reload`. В интерфейсе отдельно показаны загрузка, ошибка и успешный пустой результат. После ошибки можно повторить только нужный запрос. Список ответов выводится компонентами через `map` со стабильными ключами. Сейчас покажу эти состояния и затем объясню путь данных по файлам.

После этого сразу переходи к демонстрации. Не начинай с многоминутного рассказа о мемах, названиях моделей или сборке Worker. Это интересные дополнительные детали, но основное задание про React и API.

## 11. Сценарий защиты на 10-15 минут

### До начала

1. Открой проект в редакторе и сайт в браузере. Проверь, что сервер действительно запущен или опубликованная версия доступна.

## 12. Как воспроизвести состояния без переписывания проекта

Это инструкция для подготовки в браузере, а не утверждение, что внешний API обязан возвращать все эти состояния по команде.

### Загрузка

В Network можно временно выбрать медленное соединение вместо обычного режима. Перезагрузи страницу и посмотри на кнопку и карточки. После демонстрации верни обычную скорость. Замедление браузерной сети не означает, что серверная модель сама вычисляет ответ медленнее.

Критерий выполнен, если до окончания запросов видны состояния загрузки и кнопка имеет настоящий атрибут `disabled`. Один только изменившийся цвет кнопки не является блокировкой.

### Сетевая ошибка одного источника

В Chrome или Edge можно использовать блокировку сетевых запросов в DevTools. Названия команд немного различаются между версиями браузера. Найди в Network запрос к `api.kanye.rest`, открой его контекстное меню и включи блокировку этого адреса или домена. Запусти загрузку снова.

Ожидание: Канье показывает ошибку, сова может успешно ответить. Сними блокировку и нажми "Повторить" в карточке Канье. В Network должен появиться новый запрос Канье. Запрос совы для этого повтора не требуется.

Блокировка `/api/owl` аналогично проверяет ошибку совы. Не оставляй блокировки после защиты: иначе сайт будет выглядеть сломанным в твоём браузере.

### Пустой ответ

Используй локальную подмену ответа, например Local Overrides в Chromium DevTools. Для этого браузер может попросить выбрать отдельную локальную папку для подмен и разрешить доступ к ней. Это папка браузерного инструмента, она не нужна в репозитории проекта. Порядок настройки описан в [документации Chrome DevTools](https://developer.chrome.com/docs/devtools/overrides).

1. Найди успешный запрос Канье в Network.
2. Выбери команду подмены содержимого ответа. В подходящих версиях она называется `Override content`.
3. Замени тело ответа на `[]`, сохрани подмену и оставь успешный HTTP-статус.
4. Запусти загрузку в приложении заново.
5. Покажи сообщение "Ответ пришёл, но советов нет".
6. Удали или отключи подмену, затем снова получи обычную цитату.

Если в конкретном браузере нет такой функции, подготовь демонстрацию в браузере, где она доступна. Простое открытие URL с `[]` в отдельной вкладке не меняет состояние приложения. Редактирование и повтор HTTP-запроса в сторонней панели тоже не обязательно передаёт ответ React: важно, чтобы изменённый ответ получил именно запрос приложения.

Можно использовать тело `{"quote":"   "}`: API-функция считает строку из пробелов пустым результатом. А `{"quote":123}` должно дать ошибку формата. Это разные проверки.

### Ошибка ввода

Введи пробелы и отправь форму. Новых запросов из-за такой отправки быть не должно. Затем введи нормальный вопрос и отправь: сообщение валидации очищается при корректной отправке.

### Повтор прежнего вопроса

Добейся ошибки совы, затем измени текст в поле, не отправляя его. Восстанови сеть и нажми "Повторить" в карточке. В Payload должен быть последний отправленный вопрос, а не новый черновик. Это назначение `submittedQuestion`.

### Что вернуть после репетиции

Отключи блокировки и подмены, верни обычную скорость сети, очисти экспериментальный текст формы. Подмены DevTools не являются частью исходников и не должны попасть в Git.

## 13. Что именно смотреть в Network и Console

| Наблюдение | Что это означает |
| --- | --- |
| `POST /api/owl` | Браузер отправляет вопрос своему серверному маршруту |
| Payload `{"question":"..."}` | Тело запроса содержит вопрос, а не секретный ключ |
| Response `{"advice":"..."}` | Сервер вернул нормализованный текст совы |
| `GET https://api.kanye.rest/` | Прямой запрос к публичному источнику цитат |
| Response `{"quote":"..."}` | Исходный формат цитаты, который API-модуль преобразует |
| Запись метода и URI в Console | Отработал request interceptor Axios |
| Отменённый запрос при первом запуске в разработке | Возможная проверка очистки эффекта в StrictMode |
| Неуспешный HTTP-статус | Сервер ответил ошибкой; это отличается от полного отсутствия соединения |

В инструментах браузера виден только маршрут своего сервера. Запрос сервера к внешней модели находится на другой стороне соединения. Его нельзя ожидать отдельной строкой браузерного Network. Серверный журнал пишет статус и время, но не нужен для обязательной демонстрации клиентского перехватчика.

## 14. Вопросы преподавателя: назначение и требования

### 1. Чем пятая работа отличается от четвёртой?

В четвёртой была основа интерфейса и компонентов. Здесь появились реальные сетевые данные, управление асинхронной загрузкой, состояния результата, повтор, отдельный API-слой и Axios с перехватчиками. Внешний стиль сохранён, но учебная задача теперь про получение и показ данных.

### 2. Почему это работа на 5, а не только на 3?

Помимо запроса и вывода есть автоматическая загрузка эффектом, ошибки и пустой результат, повтор без перезагрузки, отдельные API-функции, общий HTTP-клиент, собственный хук и настроенный Axios instance с request interceptor. Показывать нужно код и поведение каждого пункта, а не просто произносить названия.

### 3. Где реальные API?

Цитаты приходят из `api.kanye.rest`. Для совы браузер вызывает `/api/owl`, а серверный обработчик отправляет запрос к Gemini API. Свой промежуточный маршрут нужен, чтобы секрет не попадал в браузер и сервер мог задать инструкцию персонажа.

### 4. Зачем два источника?

Это две независимо загружаемые карточки. Они демонстрируют общий интерфейс загрузки при разных исходных JSON. Сова отвечает на ситуацию, Канье выдаёт случайную цитату. Не нужно утверждать, что оба источника анализируют вопрос.

### 5. Где сущности проекта и список, если ответ только один?

`results` содержит карточки источников. Каждая карточка хранит массив `data` с нулём или одним текстом. Внешний `map` создаёт карточки, внутренний `map` создаёт компоненты текста. Реальная текущая модель не хранит историю и не притворяется большим каталогом. На защите нужно прямо показать оба `map` и нормализованный массив.

### 6. Почему нет базы, маршрутизатора или Redux?

Задание не требует их для этого объёма. Одной страницы, локального состояния и собственного хука достаточно. Добавление библиотек без задачи усложнило бы объяснение и сопровождение.

## 15. Вопросы преподавателя: React

### 7. Что такое компонент?

Функция, которая по входным props описывает часть интерфейса через JSX. Например, `AdviceResult` получает готовое состояние карточки и функцию повтора. Компонент не должен сам угадывать, откуда пришли данные.

### 8. Что такое JSX?

Синтаксис описания элементов внутри JavaScript. В фигурных скобках находятся выражения JavaScript. Vite с плагином React обрабатывает JSX при разработке и сборке. Браузер получает преобразованный JavaScript, а не исходный JSX без обработки.

### 9. Чем props отличаются от state?

Props передаются сверху. State хранится в экземпляре компонента или хука и обновляется через setter. `question` в `App` является state, а в `AdviceForm` тот же текст приходит как prop. Форма сообщает об изменениях через переданную функцию.

### 10. Почему нельзя присвоить `question = ...`?

Состояние обновляют через `setQuestion`. Обычное присваивание локальной переменной не сообщает React о необходимости нового рендера. В этом коде переменная ещё и объявлена через `const`, поэтому присваивание ей вообще недопустимо.

### 11. Setter сразу меняет переменную в уже выполняющемся обработчике?

Нет. Текущий обработчик видит снимок состояния своего рендера. Поэтому после `setSubmittedQuestion` запрос получает непосредственно `question.trim()`, а не рассчитывает прочитать уже обновлённый `submittedQuestion` из той же функции.

### 12. Зачем `previous => ...` в обновлении результатов?

Два запроса завершаются в разное время. Функциональное обновление получает актуальный массив на момент обработки обновления. Оно меняет только нужную карточку и сохраняет уже пришедший ответ другого источника.

### 13. Зачем копировать объект через `...result`?

Чтобы создать новый объект с сохранёнными полями и заменить нужные свойства. Нельзя менять старое состояние на месте. В нашем случае сохраняются `id`, заголовок и подпись, а обновляются `status`, `data` или `error`.

### 14. Что такое контролируемое поле?

У `textarea` значение приходит из `question`, а `onChange` вызывает `setQuestion` через prop. Источник истины находится в React. Поле и состояние не живут отдельно друг от друга.

### 15. Зачем `preventDefault()`?

Форма по умолчанию может выполнить обычную отправку с переходом страницы. Нам нужно обработать событие в React и сделать API-запрос, сохранив текущую страницу. Поэтому стандартное действие отменяется.

### 16. Зачем блокировать кнопку и ещё проверять `loading`?

`disabled` блокирует обычное взаимодействие с кнопкой и показывает состояние пользователю. Проверка в обработчике защищает логику от отправки, если обработчик всё же вызван во время текущей загрузки. Это простая защита сценария, а не универсальная серверная блокировка параллельных запросов.

### 17. Зачем `key`?

Ключ помогает React сопоставлять элементы списка между рендерами. Он должен быть стабильным и уникальным среди соседних элементов. У нас `owl` и `kanye` обозначают постоянные места источников. Это не идентификаторы, выданные внешней моделью.

### 18. Почему нельзя `Math.random()` в ключе?

Новый случайный ключ при каждом рендере заставит React считать элемент новым. Это может приводить к размонтированию и потере локального состояния. Здесь есть постоянные идентификаторы, поэтому случайность не нужна.

### 19. Что возвращает `map`?

Новый массив результатов преобразования. В JSX это массив элементов React, а в API-модуле массив объектов. Сам `map` не означает сетевой запрос: важно, какая функция передана внутрь.

### 20. Чем `some` отличается от `filter`?

`some` отвечает да или нет: есть ли хотя бы один подходящий элемент. `filter` возвращает массив подходящих элементов. Хук использует `filter` для выбора источника и `some` для вычисления общего `loading`.

## 16. Вопросы преподавателя: эффекты и собственный хук

### 21. Что такое собственный хук?

Функция с именем, начинающимся с `use`, которая использует хуки React и собирает связанную логику. `useAdvice` хранит результаты, управляет запросами и возвращает данные с действиями. Это не отдельный компонент интерфейса.

### 22. Почему не просто функция `getAdvice`?

Обычная утилита может загрузить и преобразовать данные, но сама по себе не должна вызывать React-хуки вне правил React. API-функции не зависят от React. Собственный хук связывает эти функции с состоянием и жизненным циклом компонента.

### 23. Какие правила хуков важны здесь?

Хуки вызываются на верхнем уровне React-компонента или другого хука, в одинаковом порядке. Не внутри условий, циклов, обработчиков и обычных API-утилит. Условие внутри тела эффекта допустимо: условно выполняется работа эффекта, а сам `useEffect` вызван безусловно.

### 24. Зачем `useEffect`?

Он запускает синхронизацию с внешней системой после рендера. Здесь это первоначальная загрузка и связанная с ней очистка. Запускать HTTP прямо в теле рендера нельзя: каждый рендер мог бы снова отправлять запрос.

### 25. Почему эффект зависит от `reload`?

Эффект использует эту функцию. Список зависимостей должен отражать используемые реактивные значения. `reload` стабилизирован через `useCallback`, поэтому обычное обновление результатов не создаёт новую зависимость и не запускает загрузку бесконечно.

### 26. Что делает `useCallback`?

Сохраняет ссылку на функцию между рендерами, пока не изменились зависимости. Он не вызывает функцию, не кеширует ответы API и не ускоряет саму сеть. Здесь он нужен прежде всего для стабильной зависимости эффекта.

### 27. Почему у `useCallback` пустой список зависимостей?

Функция использует постоянный массив `sources` на уровне модуля, стабильный setter React и параметры вызова. Вопрос передаётся аргументом, а не берётся из замкнутого изменяемого состояния `App`. Если бы внутри читалось изменяемое состояние, зависимости пришлось бы пересмотреть.

### 28. Почему не `useEffect(async () => ...)`?

Async-функция возвращает Promise. Эффект должен вернуть функцию очистки или ничего. Поэтому эффект синхронно создаёт контроллер, вызывает асинхронный `reload` и возвращает функцию `abort`.

### 29. Что делает очистка?

Отменяет первоначальные запросы через `AbortController`. Проверка `signal?.aborted` дополнительно предотвращает применение результата этого отменённого запуска. Очистка также нужна при проверке эффекта в режиме разработки.

### 30. Почему в разработке можно увидеть два начала загрузки?

Корневой `StrictMode` может дополнительно выполнить настройку, очистку и повторную настройку эффекта в разработке. Первая попытка отменяется. Это проверка корректности очистки, а не требование всегда дважды обращаться к API в production.

### 31. Отменяет ли этот контроллер абсолютно все запросы приложения?

Нет. Он передаётся первоначальной загрузке эффекта. Вызовы формы и повтора передают `undefined` вместо сигнала. Нельзя приписывать реализации более широкую отмену, чем в ней написано.

### 32. Почему `loading` не отдельный `useState`?

Он вычисляется из статусов: есть ли хотя бы одна карточка `loading`. Отдельное дублирующее состояние могло бы рассинхронизироваться с карточками. В текущем объёме производное значение проще.

### 33. Почему начальный status сразу `loading`?

Данные должны загрузиться автоматически после монтирования. До запуска и завершения эффекта интерфейс уже честно показывает ожидание, а не ложный успех с пустой карточкой.

### 34. Хук разделяет одно глобальное состояние между всеми вызовами?

Нет. Каждый вызов собственного хука получает своё состояние в соответствующем компоненте. В проекте он вызывается один раз в `App`, и результат передаётся дочерним компонентам.

## 17. Вопросы преподавателя: HTTP, Axios и ошибки

### 35. Зачем Axios, если есть `fetch`?

Задание на 5 требует настроенный Axios instance и перехватчики. Axios также даёт общие настройки, таймаут, JSON-обработку, конфигурацию и удобные ошибки HTTP. Нативный `fetch` остаётся в серверном обработчике, где React-клиент не нужен.

### 36. Где общий клиент?

`src/api/client.js` экспортирует `http = axios.create(...)`. Обе браузерные API-функции используют именно этот объект. Для Канье базовый адрес переопределяется в конфигурации запроса, но instance и его перехватчики остаются общими.

### 37. Где общий baseURL, если два домена?

Адреса собраны в `apiUrls`. По умолчанию `baseURL` равен `/`, а конкретный внешний источник использует `apiUrls.kanye`. Централизация не требует насильно отправлять разные источники на один домен.

### 38. Что делает request interceptor?

До отправки получает конфигурацию, пишет метод в верхнем регистре и URI, затем обязательно возвращает конфигурацию. Без возврата цепочка не получит нормальные настройки. Он не формирует ответы и не хранит состояние React.

### 39. Что делает response interceptor?

Успех пропускает дальше. При ошибке, кроме отмены, задаёт понятное сообщение: серверное сообщение, сообщение таймаута или общее сетевое. Затем возвращает отклонённый Promise, чтобы `catch` хука обработал ошибку. Он не превращает ошибку в успешный ответ.

### 40. Зачем `Promise.reject(error)`?

Чтобы сохранить ошибочный путь цепочки. Если просто вернуть объект ошибки как обычное значение, следующий код мог бы принять его за успешный результат. Перехватчик должен передать ошибку дальше, а не скрыть её.

### 41. Чем ошибка сети отличается от HTTP 500?

При HTTP 500 сервер ответил и есть HTTP-статус. При обрыве сети ответа может не быть. Поэтому в перехватчике используется `error.response?.data?.error`: `response` не гарантирован.

### 42. Где вызывается `response.json()` в Axios?

В клиентских API-функциях его нет: Axios уже предоставляет разобранное тело как `response.data`. Деструктуризация `const { data } = await ...` забирает это поле. На сервере используется нативный `fetch`, поэтому там есть `response.json()`.

### 43. Какие аргументы у POST и GET?

У `http.post` идут адрес, тело и конфигурация. У `http.get` идут адрес и конфигурация. Поэтому сигнал отмены в POST находится в третьем аргументе, а в GET во втором.

### 44. Зачем преобразовывать `advice` и `quote`?

Интерфейс должен работать с общим форматом `{ id, text }`, а не знать детали каждого поставщика. API-слой проверяет ожидаемое поле и возвращает массив. Это небольшая нормализация данных.

### 45. Что считается пустым результатом?

`null`, пустой массив или строковое поле из одних пробелов. Отсутствующее поле, число вместо строки и другой неожиданный формат считаются ошибкой. Пустой результат означает успешную обработку без текста, а не замаскированную неисправность.

### 46. Почему 65 секунд в Axios и 60 на сервере?

Сервер ограничивает ожидание внешней модели минутой. Клиенту оставлен небольшой запас, чтобы получить серверное сообщение об ошибке. Это не обещание, что ответ обязательно придёт ровно за указанное время.

### 47. `Promise.all` сам обеспечивает независимые ошибки?

Нет. Обычно отклонение одной задачи отклоняет общий Promise. Здесь каждая задача ловит собственную ошибку внутри `try/catch`, обновляет свою карточку и завершает обработку. Именно это сохраняет независимость результатов.

### 48. Запросы идут по очереди?

Нет. `map` создаёт асинхронные задачи для всех выбранных источников, и `Promise.all` ожидает их вместе. Обновление карточки происходит сразу после завершения её задачи, а не только после окончания всех.

### 49. Зачем два `undefined` при отправке?

`reload(sourceId, signal, question)` принимает три позиционных аргумента. `undefined` в первом означает все источники, во втором отсутствие сигнала. Третий аргумент остаётся вопросом. Это рабочая простая сигнатура, хотя в большом проекте можно было бы перейти к объекту параметров.

### 50. Зачем нормализовать тире в ответе?

В проекте разрешён только обычный дефис. Модель получает инструкцию, но инструкция не даёт абсолютной гарантии. Поэтому сервер дополнительно заменяет несколько Unicode-символов тире и минуса регулярным выражением. Прочие особенности стиля задаются инструкцией, а не жёстким синтаксическим валидатором.

## 18. Вопросы преподавателя: сервер, сборка и безопасность

### 51. Где находится ключ?

В серверном окружении. Обработчик читает `env.GEMINI_API_KEY`. Браузерный код его не получает. Значение не нужно показывать, коммитить или вставлять в README. Секретный ключ, однажды опубликованный в открытом месте, следует заменить у поставщика.

### 52. Почему нельзя назвать его `VITE_GEMINI_API_KEY` и читать в React?

Переменные с клиентским префиксом Vite могут быть включены в браузерную сборку. Пользователь может прочитать её содержимое. Секрет остаётся в серверном маршруте, а React отправляет только вопрос.

### 53. Почему `loadEnv(..., '')` не раскрывает всё клиенту?

Эта функция в серверной конфигурации читает переменные для серверного обработчика. Сам факт чтения не равен публикации всех значений в React. Опасность появилась бы, если бы мы вручную вставили секрет в клиентский код или настройки его подстановки.

### 54. Это Express?

Нет. Локально маршрут подключён middleware-плагином Vite. На опубликованном сайте работает Worker с методом `fetch`. Оба окружения используют общий `handleOwl`, который принимает стандартный Web Request и возвращает Web Response.

### 55. Тогда зачем Node.js?

Для инструментов разработки, Vite и скрипта сборки. Скрипт `build-server.mjs` выполняется в Node и создаёт файл Worker. Это не означает, что production запускает постоянный Express-процесс.

### 56. Что делает `build-server.mjs`?

Читает собранные статические файлы из `dist`, упаковывает их содержимое в base64 и генерирует Worker с обработчиком API. Worker на запрос страницы отдаёт HTML, JS, CSS и PNG, а на `/api/owl` запускает серверный обработчик. Base64 является способом представления байтов, а не шифрованием.

### 57. Зачем проверка Origin?

Она отвергает запрос, если присутствующий Origin не совпадает с адресом самого маршрута. Это ограничение происхождения браузерных обращений. Оно не является полноценной аутентификацией: запрос без Origin проходит эту проверку, а вне браузера заголовки можно задавать самостоятельно.

### 58. Какие проверки входа есть?

Метод POST, наличие серверного ключа, допустимый Origin, длина текстового тела и строковый `question` длиной не более 300 после обрезки пробелов. Пустая строка разрешена сервером ради первой автоматической загрузки с общим приветственным советом. Форма при ручной отправке пустоту запрещает.

### 59. Ограничение `body.length` - это строго размер в байтах?

Нет. Это длина строки JavaScript в кодовых единицах UTF-16. На сервере тело сначала читается, затем проверяется. Это простой учебный предел, а не полноценная защита памяти на уровне HTTP-сервера.

### 60. Почему сервер проверяет `response.ok`?

Нативный `fetch` обычно не отклоняет Promise только из-за HTTP 429 или 500. Нужно проверить статус. Axios по умолчанию переводит неуспешные HTTP-статусы в ошибочный путь самостоятельно.

### 61. Что означает 429?

Источник ограничил частоту или доступную квоту. Сервер возвращает понятное сообщение и статус 429. Повтор можно сделать позже. Код не подменяет реальный ответ заранее заготовленной мудростью.

### 62. Почему из ответа выбираются только части без `thought`?

Внешний формат может содержать несколько частей. Код исключает части, отмеченные как служебное размышление, берёт текст остальных, соединяет и обрезает края. Для отсутствующих полей используется безопасный переход и пустой массив. Это разбор конкретного ожидаемого формата, а не универсальный парсер всех моделей.

### 63. Гарантирует ли промт ровно 2-4 предложения?

Нет. Он задаёт желаемое поведение модели. В коде нет отдельного строгого счётчика предложений. На защите нужно различать инструкцию модели и программную валидацию результата.

### 64. Что такое alias `@`?

Короткий путь к `src`, настроенный в Vite. Например, `@/api/client` означает модуль из папки исходников. Это настройка сборщика, а не npm-пакет. Удалённый `jsconfig.json` мог помогать редактору, но runtime-правило alias остаётся в `vite.config.js`.

### 65. Что такое `package-lock.json`, почему его нет в Git?

Его автоматически создаёт npm для фиксации точных версий дерева зависимостей. В этом учебном репозитории он игнорируется по принятому решению пользователя. Обычно lock-файл коммитят для воспроизводимости установки. Называть его бессмысленным мусором неправильно: это полезный автоматически сгенерированный файл, просто он не является написанным вручную исходным кодом.

### 66. Почему `node_modules` и `dist` не в Git?

Первое содержит установленные зависимости, второе результат сборки. Их получают из исходников инструментами. В репозитории нужны исходники и конфигурация, чтобы восстановить проект. Игнорирование файла не удаляет его с диска и не удаляет автоматически уже отслеживаемый файл из Git.

### 67. Чем `dev`, `build` и `preview` отличаются?

`dev` запускает сервер разработки. `build` собирает клиент и затем Worker. `preview` локально показывает собранный клиент; наш Vite-плагин также подключает к нему API-маршрут. Публикация на Sites является отдельным действием, `npm run build` сам сайт в интернет не отправляет.

### 68. Какая версия Node нужна?

Нужна совместимая с установленной Vite 8 версия: диапазон движка текущего инструмента допускает `^20.19.0` или `>=22.12.0`. Старый Node 18 для этой установки не подходит. Версии зависимостей в `package.json` с `^` задают диапазоны, а не точную неизменную установку.

## 19. Анимация и доступность: возможные вопросы

### 69. Как сова меняет картинки без 27 отдельных файлов?

Используется один лист поз `public/owl-poses.png`. CSS задаёт размер фонового изображения, а inline-стиль меняет отрицательное смещение фона и ширину видимой области. Это спрайт: элемент показывает нужный участок общего изображения.

### 70. Кто меняет позу?

Эффект компонента `Owl` создаёт интервал при `loading = true`. Каждые 2800 миллисекунд функциональный setter увеличивает индекс по модулю длины массива. Очистка эффекта удаляет интервал, когда загрузка закончилась или компонент размонтирован.

### 71. Зачем модуль `% moments.length`?

После последнего элемента индекс снова становится нулём. Так цикл не выходит за границы массива. Количество кадров берётся из массива, а не повторяется отдельным магическим числом.

### 72. Почему картинки могут не успеть смениться?

Ответ иногда приходит быстрее 2800 миллисекунд. Код не задерживает результат ради анимации. CSS-прыжок при этом может быть заметен даже без смены подписи.

### 73. Зачем reduced motion?

Пользователь может предпочитать уменьшенное движение. CSS отключает анимации и фиксирует позу совы. Подпись статуса может продолжать меняться: отключено движение изображения, а не получение данных.

### 74. Что дают `aria-live` и `role="alert"`?

Помогают вспомогательным технологиям сообщать об изменениях без ручного перехода фокуса. В карточке используется вежливое объявление обновлений, а ошибка обозначена как alert. Это не изменяет сетевую логику и не заменяет видимый текст.

### 75. Зачем `htmlFor`, `aria-describedby` и `aria-invalid`?

`htmlFor` связывает label с полем по id. `aria-describedby` связывает поле с подсказкой и при необходимости ошибкой. `aria-invalid` сообщает, что текущий ввод не прошёл проверку. В JSX используется `className` вместо HTML-атрибута `class`.

## 20. Честные границы текущей реализации

Эти пункты нужны для точных ответов. Не начинай защиту с перечня недостатков, но не приписывай проекту отсутствующие возможности.

- Истории вопросов нет. Хранятся текущий черновик, последний отправленный вопрос и последние результаты.
- Нормализованный список каждого источника содержит максимум один текст. Это небольшой список по требованиям, а не каталог множества сущностей.
- Вопрос не отправляется Канье. Только сова отвечает по ситуации.
- Отмена в эффекте относится к первой загрузке. Ручные запросы не получили отдельный контроллер.
- Защита от одновременной отправки рассчитана на обычное поведение интерфейса. Серверной очереди и ограничения запросов на пользователя нет.
- Проверка Origin не заменяет вход пользователя и защиту от злоупотреблений.
- Перехватчик доверяет ожидаемому строковому полю серверной ошибки. Он не является универсальной схемой проверки любого JSON.
- Общий `catch` сервера относит `SyntaxError` к неправильному вопросу, хотя ошибка разбора могла бы возникнуть и при некорректном JSON внешнего ответа. Для небольшого учебного проекта обработка упрощена.
- Общий ответ 504 в остальных исключениях объединяет разные причины. Это не точная диагностика всех внутренних сбоев.
- Нужен работающий внешний API и доступная квота. Подписка на чат сама по себе не является гарантией доступности отдельного API.
- API-ключ не требуется преподавателю для чтения исходников. Для живого запуска сервера нужен настроенный секрет.
- Сборка Worker упаковывает статические файлы внутрь кода. Для маленького проекта это допустимый простой способ, для большого набора файлов обычно используют отдельное хранилище статики.

## 21. Формулировки, на которых легко ошибиться

| Неудачная фраза | Точная фраза |
| --- | --- |
| `useCallback` выполняет запрос | `useCallback` сохраняет ссылку на функцию, запрос запускает её вызов |
| `useEffect` вызывается только один раз всегда | С этой стабильной зависимостью обычные рендеры не повторяют загрузку; StrictMode в разработке проверяет эффект дополнительно |
| `Promise.all` игнорирует ошибки | Каждая задача сама ловит свою ошибку |
| Кнопка серая, значит отключена | У кнопки есть настоящий `disabled`, стиль только отражает его |
| Пустота означает ошибку | Успешный пустой результат имеет отдельный статус |
| Все запросы мира идут через Axios | Все HTTP-запросы React используют общий Axios; сервер обращается наружу через `fetch` |
| Ключ скрыт, потому что лежит в `.env` | Ключ читается только сервером и не включается в клиентскую сборку |
| Ответ совы заранее написан в проекте | В проекте есть инструкция персонажа и интерфейс, текст совета приходит от API |
| Подпись совы - ответ API | Подписи ожидания локальные, итоговый совет сетевой |
| Base64 защищает файлы | Base64 кодирует байты для упаковки, прочитать их можно обратно |
| `.gitignore` удаляет файлы | Он задаёт правила игнорирования неотслеживаемых файлов |
| Сервер написан на Express | Локально middleware Vite, при публикации Worker |

## 24. Последний лист перед защитой

- Главная мысль: реальные данные, предсказуемые состояния, повтор без перезагрузки.
- Требование на 5: собственный хук плюс Axios instance и interceptor.
- Путь: `App -> useAdvice -> advice.js -> client.js -> API -> useAdvice -> AdviceResult`.
- Автозагрузка: `useEffect`, зависимость `[reload]`, очистка через AbortController.
- Ввод: контролируемое поле, `trim`, `preventDefault`, `disabled`.
- Результат: четыре статуса, массив данных, два уровня `map`, стабильные id.
- Ошибка: отдельная карточка, понятный текст, кнопка повтора.
- Пустота: успешный ответ без элементов, отдельное сообщение.
- Сервер: ключ в окружении, клиент знает только `/api/owl`.
- Сова в ожидании: локальные смешные подписи и спрайт, сетевой ответ отдельно.
- Git: исходники и документация; зависимости, сборка и секреты игнорируются.

## 26. Как запустить проект и подготовить редактор

В терминале перейди в папку проекта. Проверь установленные версии:

```bash
node --version
npm --version
```

Нужна совместимая версия Node, описанная в вопросе 68. Если терминал не находит команду, это проблема доступности инструмента в PATH, а не ошибка React-компонента.

Установи зависимости и запусти разработку:

```bash
npm install
npm run dev
```

`npm install` читает package.json и устанавливает библиотеки. Папка node_modules и lock-файл могут появиться на диске автоматически. Они не становятся написанными тобой исходниками. Повторять установку перед каждым запуском не требуется, если зависимости уже установлены и не менялись.

Для локальной совы должен быть настроен серверный ключ. Значение задаётся в игнорируемом файле окружения или доступном серверу окружении. Не создавай для него React-константу и не добавляй клиентский префикс VITE_. После изменения серверного окружения перезапусти dev-сервер. Для опубликованного Worker используется отдельная настройка секрета хостинга; локальный файл туда автоматически не переносится.

Смотри адрес, который Vite напечатал в терминале. Часто это порт 5173, но при занятости он может выбрать другой. Открытие старого порта не проверяет новый сервер. Dev-сервер должен продолжать работать в своём терминале, пока ты пользуешься локальным сайтом.

Остановка сервера: Ctrl+C в его терминале. Для проверки готовой сборки:

```bash
npm run lint
npm run build
npm run preview
```

Линтер проверяет исходники. Сборка создаёт dist и Worker. Preview требует уже готовый dist и запускает отдельный локальный просмотр. Успешная сборка доказывает, что исходники удалось обработать, но не заменяет живую проверку API, ключа и сети.

В редакторе полезно включить номера строк. Тогда заголовок блока второго гайда, например "Строки 20-32", можно сразу сопоставить с настоящим файлом. Подготовь вкладки ядра лабораторной, а исходники библиотек из node_modules открывать на защите не нужно.

## 27. Как читать непривычный JavaScript без паники

Начинай с внешней конструкции, затем разбирай внутреннюю. В выражении `setResults(previous => previous.map(...))` сначала setter получает функцию. Эта функция получает актуальное предыдущее состояние. Внутри map создаёт новый массив. Уже внутри map выбирается новый объект нужной карточки. Это не четыре разных сетевых запроса, а одно описание обновления состояния.

`async` не делает весь браузер ожидающим. На `await` приостанавливается продолжение соответствующей асинхронной функции; интерфейс может обрабатывать события и рендерить изменения. Поэтому сова продолжает прыгать во время запроса.

Стрелочная функция не вызывается только потому, что записана. В `onRetry={() => reload(...)}` мы передаём действие на будущее нажатие. В `onRetry={reload(...)}` вызов произошёл бы сразу при вычислении JSX, и это было бы другим поведением. В текущем коде выбран правильный первый вариант.

У `map` часто встречается `result => условие ? новыйОбъект : result`. Это означает: для каждого элемента вернуть либо обновлённую копию нужной карточки, либо исходный объект остальных. Старый массив не мутируется. Само использование исходного объекта для неизменённого элемента нормально: копировать без необходимости все объекты не требуется.

`const` запрещает переприсвоить переменную, но само по себе не замораживает объект. Неизменяемость React-состояния обеспечивается способом обновления: map и новые объекты через spread, а не одним ключевым словом const.

`||` выбирает правое значение, если левое является falsy, например пустой строкой или undefined. Поэтому пустой вопрос получает общий серверный текст. `?.` решает другую задачу: безопасно прекращает доступ к свойствам при null или undefined. Эти операторы нельзя объяснять как одно и то же.

При чтении любого блока назови три вещи: что пришло на вход, что изменилось или было вычислено, что вернулось дальше. Это помогает объяснить собственный код точнее, чем заучивание названий операторов без их роли.
