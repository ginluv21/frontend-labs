## 1. Что мы вообще сделали

Есть страница с полем вопроса. Пользователь пишет ситуацию и нажимает кнопку. После обращения к сети появляются два результата:

- Сова даёт совет по введённой ситуации.
- Канье возвращает случайную цитату, не анализируя вопрос.

Пятая лабораторная проверяет, умеем ли мы получать реальные данные, хранить их в состоянии React и показывать разные исходы запроса. Красивое или мемное оформление само по себе эти требования не выполняет.

Работу удобно понимать как цепочку:

```text
Пользователь нажал кнопку
-> обработчик проверил вопрос
-> хук запустил функцию API
-> Axios отправил HTTP-запрос
-> сервер прислал ответ
-> хук обновил состояние
-> React показал результат
```

Когда источник не отвечает, путь заканчивается обновлением состояния ошибки. Когда источник прислал допустимый пустой результат, путь заканчивается состоянием пустоты. Приложение должно уметь показать оба случая.

## 2. Самые первые понятия до открытия кода

### Браузер и сервер

Браузер - программа пользователя, которая показывает страницу и выполняет её клиентский JavaScript. Сервер - программа на другой стороне соединения, которая принимает запросы и отвечает. На localhost обе программы могут находиться на одном компьютере, но обязанности у них всё равно разные.

Когда мы пишем «клиент», в этой работе обычно имеем в виду браузерную часть приложения. Когда говорим «наш сервер», имеем в виду обработчик `/api/owl`. Он может сам обратиться к ещё одному внешнему сервису.

### API

API - описанный способ взаимодействия программ. Например, программа знает: на такой адрес нужно отправить POST с вопросом, а в ответ придёт JSON с полем advice. Это договор о формате общения, а не отдельная магическая база советов.

В проекте браузер обращается к публичному API Канье и своему серверному API совы. Сервер совы отдельно общается с внешней моделью.

### HTTP-запрос

HTTP-запрос - сообщение серверу: по какому адресу обращаемся, какое действие выполняем, какие заголовки и данные передаём. Ответ содержит статус, заголовки и обычно тело с данными.

GET обычно используется для получения данных. POST позволяет передать тело запроса; в нашем случае это вопрос. Само слово POST не означает, что запись обязательно сохранена в базе: в пятой лабе сервер совы получает вопрос для генерации текста.

### JSON

JSON - текстовый формат для передачи структурированных данных. Например:

```json
{
  "advice": "Вжих-вжих! Начни с маленького шага."
}
```

В этом объекте advice - имя поля, строка справа - его значение. JSON похож на запись объекта JavaScript, но является форматом текста и имеет свои правила: двойные кавычки, отсутствие функций и комментариев.

### React-компонент

Компонент - функция, которая описывает часть интерфейса. AdviceForm описывает форму, AdviceResult карточку, Owl изображение и подписи ожидания. Компоненты позволяют разделять страницу на понятные части.

JSX - синтаксис, похожий на HTML внутри JavaScript. Например, `<AdviceResult />` обозначает элемент нашего компонента. Vite обрабатывает JSX и готовит код для браузера.

## 6. Демонстрация реальных запросов

Обновляю страницу с открытым Network.

> Запросы начинаются автоматически. Здесь POST `/api/owl` и GET к источнику цитат. Это не выбор ответа из локального массива.

В запросе совы открываю Payload:

```json
{
  "question": "Не могу начать делать домашку"
}
```

> Payload означает переданные данные запроса. Сервер получает question, добавляет инструкцию персонажа и обращается к модели. Браузер получает итоговый JSON с advice.

Открываю Response, то есть тело ответа. Объясняю, что успешный статус и ожидаемый JSON являются двумя разными проверками: сервер может ответить 200, но прислать неправильную структуру, которую наша API-функция отклонит.

У первого автоматического запроса question пустой. Сервер использует это как внутренний сценарий общего совета посетителю. Ручная форма при этом не разрешает отправить пустоту. Это осознанно разные случаи.

## 7. Axios: подробный разбор без заучивания

Открываю общий клиент:

```javascript
export const http = axios.create({
  baseURL: apiUrls.owl,
  timeout: 65000,
  headers: { Accept: 'application/json' },
})
```

> Axios - библиотека для HTTP-запросов. Instance означает настроенный экземпляр. Я один раз создаю объект http и затем использую его в функциях API.

BaseURL - базовый адрес. Для совы это корень текущего сайта. Для Канье конкретный запрос переопределяет базовый адрес, но остаётся тем же instance и сохраняет перехватчики.

Timeout - предел ожидания в миллисекундах. 65000 мс равны 65 секундам. Это не искусственная задержка: если ответ пришёл за секунду, мы не ждём ещё 64. Если времени не хватило, показываем ошибку.

Headers - заголовки, дополнительная информация сообщения. Accept говорит, какой формат ответа ожидается. Он не является самим JSON-телом, ключом модели или командой нарисовать карточку.

В API-функции:

```javascript
const { data } = await http.post('/api/owl', { question }, { signal })
```

Разбираю слева направо:

1. Http - общий клиент.
2. Post - операция с телом запроса.
3. Первый аргумент задаёт путь.
4. Второй аргумент содержит объект вопроса.
5. Третий передаёт конфигурацию, здесь сигнал отмены.
6. Await ждёт завершения Promise внутри асинхронной функции.
7. `{ data }` извлекает поле data из результата Axios.

Promise - объект, представляющий будущий результат. Запрос не может мгновенно вернуть готовый совет, поэтому возвращается обещание завершения. Async-функция возвращает Promise и разрешает использовать await. Await приостанавливает продолжение этой функции, но не выключает весь браузер: сова и другие события могут продолжать работать.

Деструктуризация - получение отдельных частей объекта или массива в переменные. `{ data }` не создаёт HTTP-запрос, а только удобно берёт нужное поле ответа. У Axios JSON обычно уже разобран, поэтому в этом клиентском коде не нужен `response.json()`.

## 8. Общий формат данных и API-модуль

Показываю конец getOwl:

```javascript
return [{ id: 'owl', text: data.advice }]
```

> Один источник называет текст advice, другой quote. Я привожу оба ответа к массиву объектов с одинаковыми полями id и text. Карточке не нужно разбираться в чужих форматах.

Это называется нормализацией: разные входы переводятся в согласованный формат нашего приложения. Сейчас в data ноль или один текст; история всех запросов не ведётся.

API-модуль - отдельный файл с функциями конкретных обращений. Он знает URL и поля внешнего JSON. Компонент знает, что нужно показать. Такое разделение позволяет менять формат сервиса в одном месте, не переписывая форму и карточку.

Если text имеет неправильный тип, функция выбрасывает Error. Throw означает прекращение нормального выполнения с исключением. Ошибка доходит до catch хука. Она не подменяется случайной заготовленной мудростью.

## 9. UseState, state, setter и рендер

Показываю создание results:

```javascript
const [results, setResults] = useState(() => sources.map(source => ({
  id: source.id, title: source.title, method: source.method,
  status: 'loading', data: [], error: '',
})))
```

> State - память React, влияющая на интерфейс. Results содержит карточки, setResults обновляет их. При обновлении React снова вычисляет нужное представление страницы.

Рендер - вычисление описания интерфейса из текущих данных. Он не обязательно означает перезагрузку HTML с сервера. React может обновить только изменившиеся части DOM. DOM - представление элементов страницы, которым управляет браузер.

Инициализатор в виде функции создаёт начальное состояние: по записи на источник. В нём нет HTTP. В development React может проверять чистоту инициализации дополнительным вызовом, поэтому нельзя прятать туда сетевой побочный эффект.

Setter не переписывает переменную внутри уже выполняющегося обработчика мгновенно. Текущий рендер видит свой снимок state. Именно поэтому после setSubmittedQuestion запрос получает подготовленный question.trim(), а не пытается прочитать уже новое значение submittedQuestion из той же функции.

## 10. Map, filter и some: три разных вопроса

### Map: что получить из каждого элемента

```javascript
const numbers = [1, 2, 3]
const doubled = numbers.map(number => number * 2)
```

Результат doubled равен `[2, 4, 6]`. Callback вызывается для каждого элемента плотного массива и возвращает его новое представление. Callback - функция, переданная другой функции для вызова. Здесь это `number => number * 2`.

Наш JSX:

```jsx
{results.map(result => <AdviceResult
  key={result.id}
  result={result}
  onRetry={() => reload(result.id, undefined, submittedQuestion)}
/>)}
```

> Для каждого объекта результата создаётся элемент AdviceResult. Получается массив элементов React.

Map с маленькой буквы здесь является методом массива. Map с большой буквы - другая встроенная коллекция пар ключ/значение, которую можно сравнивать по назначению с хеш-таблицей. В этом выражении такой коллекции нет.

Сам map не меняет исходный массив, но callback всё же мог бы вручную мутировать его объекты. В нашем обновлении используются новые объекты через spread, поэтому важно смотреть и на тело callback.

### Filter: какие элементы оставить

Filter возвращает новый массив только подходящих элементов. В reload он выбирает все источники или один источник для индивидуального повтора. Это не преобразование каждого элемента в карточку.

### Some: есть ли хотя бы один

```javascript
results.some(result => result.status === 'loading')
```

Some возвращает true или false. Пока хотя бы одна карточка загружается, форма недоступна. Новый список карточек это выражение не создаёт.

## 11. Key и props

Key - подсказка React для сопоставления соседних элементов списка между рендерами. Мы используем постоянные id источников, а не новое случайное число при каждом вызове компонента. Key должен быть уникален среди соседей, не обязательно среди всего приложения.

Props - входные значения компонента. В `result={result}` слева имя prop, справа переменная JavaScript. AdviceResult получает готовую карточку. OnRetry является prop-функцией: дочерний компонент вызывает её по нажатию.

Key является специальным свойством React и не передаётся обычным prop под именем key. Если компоненту нужен id, его передают отдельно или внутри result.

Внутри карточки есть второй map:

```jsx
{result.data.map(item => <AdviceText key={item.id} text={item.text} />)}
```

Внешний массив results хранит источники. Внутренний data хранит тексты источника. Не путай их длину: две карточки не означают два текста внутри каждой.

## 12. Собственный хук и автоматическая загрузка

> UseAdvice - собственный хук. Он использует хуки React, хранит состояние и возвращает results, loading и reload. Обычная getOwl только выполняет обращение и возвращает данные.

Хуки вызывают на верхнем уровне компонента или другого хука в одинаковом порядке. Нельзя вызывать useState только внутри if, который то сработает, то не сработает. Условная работа внутри callback эффекта допустима: сам хук всё равно вызван безусловно.

Эффект:

```javascript
useEffect(() => {
  const controller = new AbortController()
  reload(undefined, controller.signal)
  return () => controller.abort()
}, [reload])
```

UseEffect синхронизирует компонент с внешней системой после рендера. В нашем случае он запускает первоначальную сеть. Список `[reload]` является массивом зависимостей: React сравнивает значение зависимости между рендерами.

AbortController - объект управления отменой. Его signal передаётся в Axios. Return возвращает функцию очистки; стрелка не вызывает abort немедленно. Очистка срабатывает при соответствующем завершении жизненного цикла эффекта.

UseCallback сохраняет ссылку на reload при неизменных зависимостях. Ссылка - идентичность объекта функции, а не её текст. Новая функция с тем же кодом всё равно может быть другим объектом. Стабильная ссылка здесь не позволяет эффекту заново загружать данные после каждого setResults.

UseCallback не отправляет запрос сам и не кеширует ответы. Пустые зависимости допустимы потому, что используются постоянные источники, стабильный setter и аргументы вызова. Меняющийся вопрос приходит аргументом.

В StrictMode разработка может включать дополнительную проверку настройки и очистки эффекта. Отмена первой попытки и новый запуск не доказывают бесконечный цикл. В production нельзя обещать обязательную двойную загрузку.

## 13. Форма, загрузка и disabled

> Поле управляемое: value приходит из state, а onChange записывает новый текст через setter. Источник значения находится в React.

PreventDefault отменяет стандартное действие отправки HTML-формы, чтобы не переходить на новый документ. Trim удаляет пробелы с краёв. Проверка пустоты не даст отправить строку из пробелов.

Показываю кнопку:

```jsx
<Button type="submit" disabled={loading}>
  {loading ? 'СОВА НА ПОДХОДЕ...' : '★ ПОЛУЧИТЬ СОВЕТЫ ★'}
</Button>
```

> Disabled должен дойти до настоящего button. Надпись объясняет ожидание, но сама по себе не блокирует нажатие.

Общий компонент Button собирает остальные props и разворачивает их на DOM-кнопку. Поэтому disabled и onClick не теряются в обёртке.

Знак `? :` называется тернарным оператором: выбирается одно из двух значений. Здесь loading определяет текст. Выражение `условие && JSX` использовано в карточках для условного показа отдельной ветки.

## 14. Независимые ответы и функциональное обновление

Сова и Канье могут завершиться в разное время. У каждой задачи свой try/catch. Try содержит обычный путь, catch обрабатывает исключение.

Promise.all ожидает несколько задач вместе. Сам по себе он не умеет игнорировать ошибки: отклонённая задача обычно отклоняет общий Promise. У нас ошибка поймана внутри каждой задачи и превращена в обновление её карточки. Поэтому соседний успешный результат сохраняется.

При обновлении используется функциональный setter:

```javascript
setResults(previous => previous.map(result => result.id === source.id
  ? { ...result, data, status: data.length ? 'success' : 'empty' } : result))
```

Previous - актуальное предыдущее состояние на момент обработки обновления. Это важно, когда параллельно завершились две задачи. Если использовать захваченный старый массив, можно затереть результат другого запроса.

Spread `...result` копирует поля объекта. Затем data и status задают новые значения. Нужная карточка получает новый объект, остальные возвращаются без изменения. Старое состояние не мутируется на месте.

## 15. Ошибка, повтор и пустой результат

Демонстрация: блокирую запрос одного источника, получаю error, снимаю блокировку и нажимаю «Повторить».

> Повтор выполняется без перезагрузки страницы и только для выбранного источника. Question в поле может быть новым черновиком, но повтор использует submittedQuestion, то есть прежний отправленный вопрос.

Undefined в reload означает отсутствие переданного значения. В ручной отправке `reload(undefined, undefined, question.trim())` первый аргумент не ограничивает источник, второй не задаёт сигнал, третий передаёт вопрос. Это позиционные аргументы функции, а не три запроса.

Пустота проверяется отдельно. HTTP 200 с допустимым [] - успешный пустой результат. Отсутствующий text нужного типа или ошибка соединения - error. Пустой ответ не нужно маскировать под недоступность сети.

Для демонстрации empty можно через Local Overrides подменить успешное тело источника на []. Overrides - локальная подмена ответа браузером для проверки. Нужно честно сказать об этом преподавателю, затем отключить подмену. Это не удаление или изменение данных внешнего сервиса.

## 16. Interceptor: перехватчик запросов и ответов

Показываю код:

```javascript
http.interceptors.request.use(config => {
  console.log(`${config.method.toUpperCase()} ${http.getUri(config)}`)
  return config
})
```

> Interceptor - функция на пути запроса. Config содержит его настройки. Перед отправкой я печатаю метод и адрес, затем возвращаю конфигурацию, чтобы Axios продолжил работу.

ToUpperCase делает GET/POST заглавными. Шаблонная строка в обратных кавычках позволяет вставить выражения через `${...}`. GetUri собирает адрес с учётом конфигурации. Для локального маршрута вывод может быть относительным, для внешнего полным.

Response interceptor пропускает успех, а при ошибке выбирает понятное сообщение. Optional chaining `?.` безопасно обращается к вложенному свойству, когда предыдущего объекта может не быть. При сетевом сбое response не гарантирован.

Promise.reject передаёт ошибку дальше в отклонённом состоянии. Если вернуть объект ошибки как обычный успешный результат, следующий код мог бы обработать его неправильно. Отмена ERR_CANCELED исключена из обычного переписывания сообщения.

## 17. Итоговая речь и ответы преподавателю

> В работе есть реальные HTTP-запросы, результаты в useState, списки через map со стабильными key. Есть загрузка и disabled. Автоматическая загрузка запускается эффектом, предусмотрены ошибка, пустота и повтор. API-функции отдельно от UI. На уровень 5 сделаны собственный хук, общий Axios instance и request interceptor с методом и адресом.

### Почему Axios, если есть fetch?

В задании на 5 требуется настроенный Axios с перехватчиками. В проекте он также даёт общие настройки, JSON-обработку, таймаут и удобный путь обработки HTTP-ошибок. На сервере совы fetch остаётся внутренней реализацией backend.

### Почему не все запросы идут прямо из React?

Секрет модели должен остаться на сервере. Браузерный код доступен пользователю. Файл .env сам по себе не защищает значение, если затем подставить его в клиентскую сборку. Секрет не получает префикс VITE_ и не экспортируется в React.

### Где находится API-ключ в Network?

В браузерном запросе его нет. Он используется сервером при следующем обращении к внешнему сервису. На проекторе показываем имя переменной, а не её содержимое.

### Отменяются абсолютно все запросы приложения?

Нет. В пятой лабе контроллер эффекта относится к первоначальной загрузке. Ручные вызовы не получили такой же собственный сигнал. Клиентская отмена также не гарантирует остановку всей уже начавшейся работы внешнего сервиса.

### Зачем анимация и влияет ли она на скорость?

Анимация показывает ожидание, но не задерживает готовый ответ. Интервал совы управляет локальным индексом кадра, а HTTP имеет отдельные механизмы ожидания и таймаута.

### Откуда большие файлы после установки?

Node_modules содержит библиотеки, package-lock создаётся npm, dist получается сборкой. Они не написаны вручную. В этом репозитории они игнорируются. В обычных проектах lock-файл часто коммитят ради точных версий.

## 19. Как читать короткую запись JavaScript

Стрелка `=>` обозначает стрелочную функцию. Запись `item => item.text` означает: принять item и вернуть его text. Если после стрелки нет блока фигурных скобок, выражение возвращается автоматически. С блоком обычно нужен явный return.

`===` сравнивает без неявного приведения типов: строка и число не становятся одинаковыми только из-за похожей записи. `!value` означает логическое отрицание, а `||` выбирает запасное значение, если слева falsy. Falsy - значения вроде пустой строки, false, null и undefined, которые считаются ложными в условии.

Фигурные скобки имеют разные роли по месту: объект `{ question }`, блок функции и выражение JavaScript внутри JSX не являются одной конструкцией. В JSX `text={question}` правая пара скобок разрешает использовать переменную вместо буквального текста question.

Метод - функция, доступная как свойство объекта, например массив.map. Аргумент - конкретное значение при вызове. Параметр - имя, под которым функция принимает это значение в определении. У getOwl параметр question, а строка из формы является переданным аргументом.

## 20. Как репетировать и что считать доказательством

Первый проход сделай без редактора: расскажи путь данных обычными словами. Второй проход сделай с сайтом и Network. Третий - с пятью основными файлами. Такой порядок помогает связать смысл с синтаксисом, а не механически прочитать строки.

Сборка подтверждает возможность обработать исходники. Успешный запрос подтверждает конкретное сетевое обращение. Правильная карточка подтверждает отображение состояния. Ни одно из этих доказательств не заменяет остальные.

Не выдавай пример текста в гайде за реально полученный сейчас ответ. При последней проверке реализации шестой версии внешние источники возвращали ошибки; этот исторический результат не является новой проверкой пятой. Перед выступлением сделай живой запуск нужной версии и честно отдели недоступность внешнего сервиса от ошибки своего UI.

Нельзя обещать гарантированную оценку одним только перечнем библиотек. Нужно показать поведение и объяснить его на коде. Для короткой защиты достаточно вступления, успешной загрузки, ошибки с повтором, пустоты и файлов client/useAdvice/AdviceResult.
