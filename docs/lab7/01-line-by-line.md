# Лабораторная 7: подробный построчный разбор изменений

Дата подготовки: 10 ноября 2026 года. Материал относится к TypeScript-коду этой папки проекта.

Это разбор именно седьмой работы. Сова, две страницы, копилка, запросы Axios, Zustand и TanStack Query появились раньше. Здесь объясняются добавленные типы, проверки, настройки и числовое поле. Старый сервер и алгоритм базы заново не разбираются. Если файл приведён целиком, прежние строки включены только для понимания новых типов.

Номера в таблицах совпадают со строками исходных файлов на момент подготовки. В блоках кода нет добавленных комментариев и номеров: блок можно сравнить с редактором. Пустые строки разделяют части программы и отдельно не разбираются. Закрывающие скобки тоже объяснены, потому что начинающему важно видеть границы блока.

Сначала читай цель блока, потом его код, затем таблицу. После таблицы попробуй ответить на контрольный вопрос своими словами. Второй файл `02-defense-guide.md` связывает эти отдельные знания в объяснение для защиты.

## 1. Что изменилось относительно шестой работы

| Часть | Что было | Что добавлено в лабораторной 7 |

В `src` нет оставшихся `.js` и `.jsx`. Серверные адаптеры, настройка Vite и упаковщик сайта оставлены на JavaScript: в этой работе типизируется клиентское React-приложение. Эти файлы относятся к инфраструктуре прошлой работы и не входят в `include` конфигурации TypeScript. Не говори на защите, что серверные `.js` тоже проверяет `tsc`.

## 2. Настройка и команды

В `package.json` добавлены `typescript` и команда `typecheck`. Команда `build` сначала выполняет проверку типов. `tsc --noEmit` анализирует программу и не создаёт JavaScript-файлы. Рабочую браузерную сборку по-прежнему делает Vite.

```json
{
  "build": "npm run typecheck && vite build && node scripts/build-server.mjs",
  "typecheck": "tsc --noEmit"
}
```

Первое `&&` означает: запускать Vite только после успешной проверки типов. Второе запускает упаковщик только после успешного Vite. Код возврата 0 означает успех. Ненулевой код останавливает цепочку. В отдельной команде `npm run typecheck` можно быстро проверить типы, не собирая весь сайт.

`package-lock.json` теперь не игнорируется. В `package.json` описаны допустимые версии, а lock-файл фиксирует конкретные установленные версии. `npm ci` устанавливает именно их и проверяет согласованность двух файлов. Для сдачи нужны оба файла. Сама папка `node_modules` в Git не добавляется.

## 3. tsconfig.json: что именно проверяет компилятор

```json
    "noUnusedParameters": true,
    "verbatimModuleSyntax": true,
    "skipLibCheck": true,
    "noEmit": true,
    "types": ["vite/client"],
    "paths": { "@/*": ["./src/*"] }
```

## 4. Общие типы: Advice, SavedAdvice и состояния

Файл: `src/types/advice.ts`, строки 1-33.

Это словарь проекта. Он не создаёт советы и не отправляет запросы. В одном месте описано, какие объекты разрешены. Константа sourceNames в конце является обычными рабочими данными, остальные объявления служат проверке типов.

```ts
export type AdviceSource = 'owl' | 'kanye'

export type SourceFilter = AdviceSource | 'all'

export interface Advice {
  id: string
  text: string
}

export interface SavedAdvice extends Advice {
  source: AdviceSource
}

export type NewAdvice = Pick<SavedAdvice, 'source' | 'text'>

export type AdviceTextProps = Omit<SavedAdvice, 'id'>

export type AdviceState =
  | { status: 'loading' }
  | { status: 'error'; error: string }
  | { status: 'empty' }
  | { status: 'success'; data: Advice[] }

export type AdviceResultData = {
  id: AdviceSource
  title: string
  method: string
} & AdviceState

export const sourceNames: Record<AdviceSource, string> = {
  owl: 'Сова',
  kanye: 'Канье',
}
```

Контрольный вопрос: можно ли создать `{ status: "loading", data: [] }` как отдельный вариант AdviceState? В нашем описании data относится только к success. Это помогает не смешивать состояния. При проверке свежего объектного литерала лишнее поле будет ошибкой.

## 5. Проверки внешних данных вместо утверждения типа

Файл: `src/api/validation.ts`, строки 1-17.

Описать interface недостаточно: сервер способен прислать null, строку или объект другой формы. Эти функции выполняются во время работы сайта. Проверка возвращает новый объект с нужными полями только после проверки их значений.

```ts
import type { AdviceSource, SavedAdvice } from '@/types/advice'

export function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value)
}

export function isAdviceSource(value: unknown): value is AdviceSource {
  return value === 'owl' || value === 'kanye'
}

export function readSavedAdvice(value: unknown): SavedAdvice {
  if (!isRecord(value) || typeof value.id !== 'string'
    || !isAdviceSource(value.source) || typeof value.text !== 'string') {
    throw new Error('Копилка прислала непонятный ответ.')
  }
  return { id: value.id, source: value.source, text: value.text }
}
```

| Строка файла | Объяснение |
| --- | --- |
| 1 | Импортирует только описания типов. Этот импорт не нужен браузеру после сборки. |
| 3 | Параметр имеет тип unknown: заранее не доверяем форме входа. `value is Record<string, unknown>` сообщает компилятору результат успешной проверки. |
| 4 | Сначала проверяет объект, затем исключает null и массив. Порядок важен: typeof null тоже возвращает object. |
| 5 | Закрывает ранее открытый блок или вызов. Сверяй отступ, чтобы понять, к какой конструкции относится скобка. |
| 7 | Объявляет проверку допустимого источника. После true значение можно использовать как AdviceSource. |
| 8 | Проверяет два разрешённых строковых значения реальными сравнениями. |
| 9 | Закрывает ранее открытый блок или вызов. Сверяй отступ, чтобы понять, к какой конструкции относится скобка. |

## 6. Свой полезный generic toArray

Файл: `src/utils/toArray.ts`, строки 1-3.

Оба источника возвращают один текст, а карточка работает со списком ответов. Функция приводит одну запись к массиву. Она не зависит от конкретных полей совета и не теряет их тип.

```ts
export function toArray<T>(value: T | T[]): T[] {
  return Array.isArray(value) ? value : [value]
}
```

| Строка файла | Объяснение |
| --- | --- |
| 1 | T является параметром типа. Входом может быть один T или массив T[], результат всегда T[]. |
| 2 | Если вход уже массив, возвращает его. Иначе создаёт массив из одного значения. Числа, тексты и Advice используют одну реализацию. |
| 3 | Закрывает ранее открытый блок или вызов. Сверяй отступ, чтобы понять, к какой конструкции относится скобка. |

Когда вызвано toArray<Advice>, вместо T подставляется Advice. Это описание проверки, а не дополнительный объект T в памяти браузера. Generic не проверяет неизвестный JSON: перед вызовом данные уже должны быть проверены.

## 7. Ошибка тоже начинается с unknown

Файл: `src/utils/errors.ts`, строки 1-3.

В JavaScript можно выбросить не только Error, но и строку, null или другой объект. Поэтому вспомогательная функция не предполагает, что у любого входа есть message.

```ts
export function getErrorMessage(error: unknown): string {
  return error instanceof Error ? error.message : 'Произошла неизвестная ошибка.'
}
```

| Строка файла | Объяснение |
| --- | --- |
| 1 | Принимает любую ошибку как unknown и гарантирует строковый результат. |
| 2 | instanceof Error проверяет, является ли значение настоящей ошибкой. Только после этого читается message; иначе используется понятный запасной текст. |
| 3 | Закрывает ранее открытый блок или вызов. Сверяй отступ, чтобы понять, к какой конструкции относится скобка. |

Контрольный вопрос: почему нельзя сразу написать error.message у unknown? Компилятор ещё не знает, что error вообще является объектом с таким полем.

## 8. Типизированные запросы к сове и Канье

Файл: `src/api/advice.ts`, строки 1-24.

Сетевой код остался отдельным от компонентов. Главное изменение - граница доверия: Axios получает unknown, функция проверяет ответ, а компонент получает уже Advice[].

```ts
import { http, apiUrls } from '@/api/client'
import { isRecord } from '@/api/validation'
import { toArray } from '@/utils/toArray'
import type { Advice } from '@/types/advice'

export async function getOwl(signal?: AbortSignal, question = ''): Promise<Advice[]> {
  const { data } = await http.post<unknown>('/api/owl', { question }, { signal })
  if (data === null || (Array.isArray(data) && data.length === 0)) return []
  if (!isRecord(data) || typeof data.advice !== 'string') {
    throw new Error('Сова прислала непонятный ответ.')
  }
  if (!data.advice.trim()) return []
  return toArray<Advice>({ id: 'owl', text: data.advice })
}

export async function getKanye(signal?: AbortSignal): Promise<Advice[]> {
  const { data } = await http.get<unknown>('/', { baseURL: apiUrls.kanye, signal })
  if (data === null || (Array.isArray(data) && data.length === 0)) return []
  if (!isRecord(data) || typeof data.quote !== 'string') {
    throw new Error('Источник прислал непонятную цитату.')
  }
  if (!data.quote.trim()) return []
  return toArray<Advice>({ id: 'kanye', text: data.quote })
}
```

| 2 | Подключает указанные функции или компоненты из другого модуля. Это рабочий импорт, который нужен при выполнении. |
| 3 | Подключает указанные функции или компоненты из другого модуля. Это рабочий импорт, который нужен при выполнении. |

## 9. Типы чтения и записи копилки

Файл: `src/api/saved.ts`, строки 1-14.

```ts
import { http } from '@/api/client'
import { readSavedAdvice } from '@/api/validation'
import type { NewAdvice, SavedAdvice } from '@/types/advice'

export async function getSaved({ signal }: { signal: AbortSignal }): Promise<SavedAdvice[]> {
  const { data } = await http.get<unknown>('/api/saved', { signal })
  if (!Array.isArray(data)) throw new Error('Копилка прислала непонятный список.')
  return data.map((item: unknown) => readSavedAdvice(item))
}

export async function saveAdvice(advice: NewAdvice): Promise<SavedAdvice> {
  const { data } = await http.post<unknown>('/api/saved', advice)
  return readSavedAdvice(data)
}
```

## 11. Хук и типизированное состояние запроса

Файл: `src/hooks/useAdvice.ts`, строки 1-34.

Хук оставляет серверные ответы в TanStack Query. Мы не делаем второй массив в Zustand или useState. Собственный union нужен для понятной карточке формы состояния.

```ts
import { useQuery } from '@tanstack/react-query'
import type { UseQueryResult } from '@tanstack/react-query'
import { getOwl, getKanye } from '@/api/advice'
import type { Advice, AdviceSource, AdviceState, AdviceResultData } from '@/types/advice'
import { getErrorMessage } from '@/utils/errors'

function getState(query: UseQueryResult<Advice[], Error>): AdviceState {
  if (query.isFetching || query.isPending) return { status: 'loading' }
  if (query.isError) return { status: 'error', error: getErrorMessage(query.error) }
  if (!query.data || query.data.length === 0) return { status: 'empty' }
  return { status: 'success', data: query.data }
}

export function useAdvice(question: string) {
  const owl = useQuery<Advice[], Error>({
    queryKey: ['advice', 'owl', question],
    queryFn: ({ signal }) => getOwl(signal, question),
  })
  const kanye = useQuery<Advice[], Error>({
    queryKey: ['advice', 'kanye'],
    queryFn: ({ signal }) => getKanye(signal),
  })
  const results: AdviceResultData[] = [
    { id: 'owl', title: 'Ответ совы', method: 'Мудрость на высоте одного прыжка.', ...getState(owl) },
    { id: 'kanye', title: 'Канье на связи', method: 'Высказался. К вопросу не присматривался.', ...getState(kanye) },
  ]

  function reload(sourceId?: AdviceSource): void {
    if (!sourceId || sourceId === 'owl') void owl.refetch()
    if (!sourceId || sourceId === 'kanye') void kanye.refetch()
  }

  return { results, loading: results.some(result => result.status === 'loading'), reload }
}
```

## 12. Карточка: discriminated union и switch

Файл: `src/components/AdviceResult.tsx`, строки 1-41.

Теперь у loading нет массива данных, а у success нет поля error. Общая метка status позволяет TypeScript определить доступные поля внутри каждой ветки. Это и есть discriminated union, то есть объединение с различающим полем.

```tsx
import { Button } from '@/shared/Button'
import { SaveButton } from '@/components/SaveButton'
import type { ReactNode } from 'react'
import type { AdviceResultData, AdviceTextProps } from '@/types/advice'

function AdviceText({ source, text }: AdviceTextProps) {
  return <div><blockquote>{text}</blockquote><SaveButton source={source} text={text} /></div>
}

interface AdviceResultProps {
  result: AdviceResultData
  onRetry: () => void
}

export function AdviceResult({ result, onRetry }: AdviceResultProps) {
  let content: ReactNode = null

  switch (result.status) {
    case 'loading':
      content = <p role="status">Сова ещё прыгает. Мысль на подходе...</p>
      break
    case 'error':
      content = <div role="alert"><p>{result.error}</p><Button onClick={onRetry}>Повторить</Button></div>
      break
    case 'empty':
      content = <p>Ответ пришёл, но советов нет. Даже сове нечего добавить.</p>
      break
    case 'success':
      content = result.data.map(item => <AdviceText key={`${item.id}:${item.text}`} source={result.id} text={item.text} />)
      break
  }

  return (
    <section className="result" aria-live="polite" aria-busy={result.status === 'loading'}>
      <h2>{result.title}</h2>
      <p className="source-method">{result.method}</p>
      {content}
      {result.status === 'success' && <p className="source-method">{result.id === 'owl' ? 'Сказала и поскакала.' : 'Оригинал на английском'}</p>}
    </section>
  )
}
```

## 19. Число из input: строка, проверка и nullable useState

Файл: `src/pages/SavedPage.tsx`, строки 1-46.

Это единственное новое поведение страницы: пользователь выбирает, сколько последних советов показать. Поле относится к уже существующей копилке и добавлено для явного числового пункта задания. Ввод не меняет записи базы: slice ограничивает только показанный список.

```tsx
import { useQuery } from '@tanstack/react-query'
import { getSaved } from '@/api/saved'
import { useFilter } from '@/store/useFilter'
import { Button } from '@/shared/Button'
import { useState } from 'react'
import type { ChangeEvent } from 'react'
import { sourceNames } from '@/types/advice'

export function SavedPage() {
  const [limitInput, setLimitInput] = useState('10')
  const [limit, setLimit] = useState<number | null>(10)
  const source = useFilter(state => state.source)
  const saved = useQuery({ queryKey: ['saved'], queryFn: getSaved })
  const items = (saved.data || []).filter(item => source === 'all' || item.source === source).slice(0, limit ?? 0)

  function handleLimitChange(event: ChangeEvent<HTMLInputElement>): void {
    const text = event.target.value
    setLimitInput(text)
    const number = Number(text)
    if (!text.trim() || !Number.isInteger(number) || number < 1 || number > 50) {
      setLimit(null)
      return
    }
    setLimit(number)
  }

  return (
    <section className="saved-page" aria-live="polite" aria-busy={saved.isFetching}>
      <h2>Копилка советов</h2>
      <p>Общая для всех посетителей. Сова складывает, мы перечитываем.</p>
      <label htmlFor="saved-limit">Сколько советов показать (1-50):</label>
      <input id="saved-limit" type="number" min="1" max="50" step="1" value={limitInput} onChange={handleLimitChange} aria-invalid={limit === null} aria-describedby={limit === null ? 'limit-error' : undefined} />
      {limit === null && <p id="limit-error" role="alert">Введи целое число от 1 до 50.</p>}
      {saved.isPending && <p role="status">Сова роется в копилке...</p>}
      {saved.isFetching && !saved.isPending && <p role="status">Обновляем копилку...</p>}
      {saved.isError && <div role="alert"><p>{saved.error.message}</p><Button disabled={saved.isFetching} onClick={() => saved.refetch()}>Повторить</Button></div>}
      {saved.isSuccess && limit !== null && items.length === 0 && <p>{saved.data.length ? 'По этому фильтру советов пока нет.' : 'Копилка пустая. Сохрани первый совет на главной.'}</p>}
      {items.map(item => (
        <article className="result" key={item.id}>
          <h2>{sourceNames[item.source]}</h2>
          <blockquote>{item.text}</blockquote>
        </article>
      ))}
    </section>
  )
}
```

## 21. Проверка элемента массива по индексу

Файл: `src/components/Owl.tsx`, строки 21-31.

Выражение `moments[step] ?? idle` даёт запасную позу, когда элемента по индексу нет. В анимации по-прежнему используется старый таймер, но объект для JSX теперь гарантированно существует.

```tsx
export function Owl({ loading }: { loading: boolean }) {
  const [step, setStep] = useState(0)

  useEffect(() => {
    if (!loading) return
    const timer = setInterval(() => setStep(previous => (previous + 1) % moments.length), 2800)
    return () => clearInterval(timer)
  }, [loading])

  const idle: OwlMoment = { x: -1045, y: -410, text: 'Сова попалась. Теперь послушаем, что скажет.' }
  const moment = loading ? moments[step] ?? idle : idle
```

| --- | --- |
| 21 | Props компонента требуют boolean loading. Строку вместо флага передать нельзя. |
| 22 | Состояние step однозначно выводится как number из начального 0. |
| 24 | Эффект синхронизирует таймер с флагом загрузки. Сам useEffect был и раньше. |
| 25 | Если загрузки нет, таймер не создаётся. |
| 26 | Меняет индекс по кругу каждые 2800 миллисекунд. Остаток от деления удерживает обычную анимацию в границах массива. |

## Что было только переименовано

`App.jsx` стал `App.tsx`, `Disclaimer.jsx` стал `Disclaimer.tsx`, `queryClient.js` стал `queryClient.ts`. Их JSX и поведение не потребовали новых пользовательских типов. У компонентов без props результат выводится автоматически. Поэтому длинный дисклеймер и старый роутинг здесь заново не разбираются.

`index.html` теперь загружает `/src/main.tsx`. В `main.tsx` импорт App больше не содержит старое расширение `.jsx`. Типы не работают, если браузерная точка входа продолжает указывать на удалённый файл.

Для поля числа добавлены только ширина и отступ в `App.css`, а input и select получили общий шрифт в `index.css`. Эти CSS-правила не реализуют проверку числа: это делает JavaScript-обработчик.

## Чего этот код не обещает

TypeScript не делает внешний API доступным и не продлевает ключ. Ошибка сервиса остаётся нормальным состоянием error. Тип Promise описывает успешный результат, а не гарантирует отсутствие отклонения. Проверки клиента не отменяют серверные проверки POST. Общая копилка не стала личной: авторизация и схема базы в этой лабораторной не менялись.

Во время исполнения типы interface, union, Pick и Omit уже удалены. Остаются реальные if, typeof, instanceof, Number, map и сетевые запросы. На защите обязательно различай эти две группы.
