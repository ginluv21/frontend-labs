# Лабораторная работа 6: полный построчный разбор

Снимок кода: 27 октября 2026 года, ветка `lab6-state`. [Первый гайд](01-defense-guide.md) объясняет сценарий защиты, соответствие требованиям и возможные вопросы. Этот документ нужен, чтобы разобраться в любой строке текущей версии.

## Правило чтения

Для каждого файла: назначение -> небольшой блок -> точный код -> объяснение каждой строки -> следующий блок. Номера относятся к настоящему исходному файлу. Они не вставлены в код, чтобы фрагмент можно было сравнить или скопировать. Пустые строки и закрывающие скобки тоже учитываются. Сжатая строка CSS объясняется со всеми её свойствами.

## Граница полного покрытия

Здесь полностью разобраны 29 собственных текстовых исходников и конфигураций текущего приложения: React, JavaScript, CSS, HTML, SQL, манифест npm, журнал миграции и правила Git. Нет выборочных пропусков старых компонентов: сова, дисклеймер и неизменённые API-функции тоже включены.

Не копируются внутренности npm-библиотек, node_modules, автоматически получаемый lock-файл, dist, бинарная картинка public/owl-poses.png, файл базы .data/saved.sqlite, секреты и служебные игнорируемые настройки среды. README и учебные гайды являются документацией, а не исполняемыми модулями; включение гайда в собственный построчный разбор создало бы бессмысленную рекурсию. Роль изображения и конфигурации хостинга объясняется там, где они используются. Сам API-ключ отсутствует.

В отличие от пятой лабы, сейчас нет сетевого useEffect в useAdvice: запросы выполняют query-хуки. Не переносите старое объяснение useCallback и собственного AbortController на этот изменившийся файл.

## Четыре контекста выполнения

1. Браузер: компоненты, Zustand, TanStack Query, Axios.
2. Локальный Node: Vite и local-db с SQLite-файлом.
3. Production Worker: серверные handleOwl и handleSaved, привязка D1.
4. Сборка Node: скрипт читает файлы и генерирует Worker. Код внутри шаблонной строки запустится позднее на хостинге.

Не объясняй одну строку так, будто она работает сразу во всех четырёх местах. Например, node:sqlite не отправляется в браузер и не используется Worker вместо D1.

### Строки 1-8. Импорты

**Что делает блок и зачем:** Подключает провайдеры, клиент и корневой компонент.

```jsx
import { StrictMode } from 'react'

```

**Построчно:**

- **Строка 1.** Импортируется StrictMode для дополнительных проверок разработки. Это не отдельная страница сайта.
- **Строка 2.** Импортируется createRoot для монтирования React в HTML-контейнер.
- **Строка 3.** Импортируется BrowserRouter для адресов и истории. Он должен оборачивать компоненты, использующие NavLink и Routes.
- **Строка 4.** Импортируется QueryClientProvider. Через его контекст useQuery и useMutation получают общий клиент.
- **Строка 5.** Импортируется уже созданный queryClient по alias @. Здесь не создаётся новый клиент при каждом изменении страницы.
- **Строка 6.** Подключается глобальный CSS страницы.
- **Строка 7.** Импортируется корневой компонент App.
- **Строка 8.** Пустая строка отделяет импорты от запуска.

### Строки 9-17. Дерево провайдеров

**Что делает блок и зачем:** Все страницы и кнопки находятся внутри одного QueryClientProvider и BrowserRouter.

```jsx
createRoot(document.getElementById('root')).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <BrowserRouter>
        <App />
      </BrowserRouter>
    </QueryClientProvider>
  </StrictMode>,
)
```

**Построчно:**

- **Строка 9.** По id root находится контейнер из index.html, создаётся React root и начинается render дерева.
- **Строка 10.** Открывается StrictMode. В development возможны дополнительные проверки жизненного цикла.
- **Строка 11.** Провайдер получает queryClient как prop client. Все вложенные компоненты используют тот же кеш.
- **Строка 12.** Открывается BrowserRouter, общий для всей навигации приложения.
- **Строка 13.** Внутри обоих провайдеров создаётся App с оболочкой и маршрутами.
- **Строка 14.** Закрывается BrowserRouter.
- **Строка 15.** Закрывается QueryClientProvider; при переключении его внутренних страниц он не размонтируется вместе с ними.
- **Строка 16.** Закрывается StrictMode. Завершающая запятая допустима в вызове JavaScript.
- **Строка 17.** Закрывается render.

### Строки 1-2. Импорт

**Что делает блок и зачем:** Подключает фабрику Zustand.

```javascript

```

**Построчно:**

- **Строка 1.** Импортируется именованная функция create из Zustand. Это фабрика store, а не React useState.
- **Строка 2.** Пустая строка отделяет импорт от определения состояния.

### Строки 3-6. Создание одного store

**Что делает блок и зачем:** Выполняется на уровне модуля, а компоненты позже только подписываются.

```javascript
export const useFilter = create(set => ({
  source: 'all',
  setSource: source => set({ source }),
}))
```

**Построчно:**

- **Строка 3.** Create получает функцию настройки и возвращает хук useFilter. Параметр set предоставлен Zustand для обновления; вызов расположен вне компонентов.
- **Строка 4.** Начальное значение source равно all, то есть показывать оба источника. Эта строка используется и в select, и в фильтрации страниц.
- **Строка 5.** Действие setSource принимает новую строку и вызывает set с объектом. Сокращение { source } означает поле с именем source; поверхностное обновление сохраняет остальные части store.
- **Строка 6.** Закрываются объект состояния, callback настройки и вызов create. Export делает один полученный хук доступным всем потребителям.

### Связать store с интерфейсом

SourceFilter вызывает setSource. После обновления подписки AdvicePage и SavedPage получают ту же строку. Они фильтруют свои массивы в рендере. Никакой записи в базу, очистки query-кеша или запроса из самого setSource нет. Полная перезагрузка создаёт новый документ и исходный source=all.

## 8. `src/api/queryClient.js`

Единый QueryClient с настройками чтения и записи. Он не создаётся повторно при рендере.

[Открыть исходник](../../src/api/queryClient.js).

### Строки 1-2. Импорт

**Что делает блок и зачем:** Берёт класс клиента из TanStack Query.

```javascript

```

**Построчно:**

- **Строка 1.** Импортируется QueryClient. Это класс организации серверного кеша в браузерном приложении.
- **Строка 2.** Пустая строка отделяет импорт от создания экземпляра.

### Строки 3-8. Общие настройки

**Что делает блок и зачем:** Устанавливает свежесть и предсказуемое поведение повторов для всех наших query и mutation.

```javascript
export const queryClient = new QueryClient({
  defaultOptions: {
    queries: { staleTime: 60000, retry: false, refetchOnWindowFocus: false },
    mutations: { retry: false },
  },
})
```

**Построчно:**

- **Строка 3.** Создаётся и экспортируется один экземпляр. New выполняется при загрузке модуля, а не внутри App.
- **Строка 4.** Открывается defaultOptions для общих настроек запросов и действий записи.
- **Строка 5.** Query-данные считаются свежими 60000 мс; автоматические retry и обновление при фокусе отключены. Это не задаёт удаление кеша и не включает периодический опрос.
- **Строка 6.** У mutation также отключены автоматические повторные попытки. Пользовательская повторная отправка остаётся возможной.
- **Строка 7.** Закрывается defaultOptions.
- **Строка 8.** Закрываются объект конфигурации и создание QueryClient. GcTime не указан и остаётся библиотечным значением по умолчанию.

### Не перепутать времена

StaleTime 60 секунд определяет свежесть, не удаляет запись и не является setInterval. GcTime здесь не указан: для неактивного клиентского query остаётся библиотечное время около 5 минут. Инвалидация может пометить данные устаревшими раньше минуты. Полный reload страницы создаёт новый клиент без persistence.

### Строки 19-26. Перехватчик ответов

**Что делает блок и зачем:** Переводит типовые ошибки в понятный текст и сохраняет отклонение Promise.

```javascript
http.interceptors.response.use(response => response, error => {
  if (error.code !== 'ERR_CANCELED') {
    error.message = error.response?.data?.error || (error.code === 'ECONNABORTED'
      ? 'Сова не дождалась ответа. Попробуй ещё раз.'
      : 'Источник недоступен. Проверь соединение и попробуй ещё раз.')
  }
  return Promise.reject(error)
})
```

**Построчно:**

- **Строка 19.** Регистрируется response interceptor с двумя callback: успешный ответ возвращается как есть, ошибка обрабатывается отдельно.
- **Строка 20.** Отмена с кодом `ERR_CANCELED` исключается из переписывания сообщения. Отменённая задача не должна выглядеть как обычная неисправность источника.
- **Строка 21.** Сначала берётся сообщение своего сервера из `error.response?.data?.error`. Optional chaining нужен, потому что при сетевом сбое ответа может не быть; `||` выбирает запасной вариант.
- **Строка 22.** Если код `ECONNABORTED`, выбирается сообщение о таймауте. Это первая ветка тернарного выражения, начатого на предыдущей строке.
- **Строка 23.** Иначе выбирается общее сообщение о недоступности источника. Закрывается выражение запасного текста.
- **Строка 24.** Закрывается условие, исключавшее отмену. Ошибка продолжит движение дальше в любом случае.
- **Строка 25.** Возвращается отклонённый Promise. Так `catch` вызывающего хука получит ошибку, а не ложный успешный результат.
- **Строка 26.** Закрываются callback ошибки и вызов регистрации response interceptor.

### Строки 3-10. Ответ совы

**Что делает блок и зачем:** Отправляет вопрос своему серверу и проверяет поле advice.

```javascript
export async function getOwl(signal, question = '') {
  const { data } = await http.post('/api/owl', { question }, { signal })
  if (data === null || (Array.isArray(data) && data.length === 0)) return []
  if (typeof data.advice !== 'string') throw new Error('Сова прислала непонятный ответ.')
  if (!data.advice.trim()) return []
  return [{ id: 'owl', text: data.advice }]
}

```

**Построчно:**

- **Строка 3.** Экспортируется асинхронная функция совы. Она принимает необязательный сигнал отмены и вопрос, по умолчанию пустую строку для первоначальной загрузки.
- **Строка 4.** POST отправляет JSON-объект `{ question }` на `/api/owl`. Третий аргумент содержит `signal`; из готового Axios-ответа извлекается поле `data`.
- **Строка 5.** `null` и настоящий пустой массив превращаются в пустой результат `[]`. Проверка `Array.isArray` не принимает произвольный объект за массив.
- **Строка 6.** Проверяется тип `advice`. Если ожидаемой строки нет, выбрасывается ошибка формата, которую поймает хук.
- **Строка 7.** Строка из одних пробелов считается успешным отсутствием текста. `trim()` используется для проверки, исходная строка здесь ещё не заменяется.
- **Строка 8.** Непустой текст упаковывается в массив из одного объекта. `owl` является постоянным id логического места, `text` является общим именем поля для интерфейса.
- **Строка 9.** Закрывается функция загрузки совы.
- **Строка 10.** Пустая строка отделяет две независимые функции API.

```javascript
  if (data === null || (Array.isArray(data) && data.length === 0)) return []
  if (typeof data.quote !== 'string') throw new Error('Источник прислал непонятную цитату.')
  if (!data.quote.trim()) return []
  return [{ id: 'kanye', text: data.quote }]
}
```

**Построчно:**

- **Строка 11.** Экспортируется асинхронная функция Канье. Вопрос ей не нужен; используется только сигнал.
- **Строка 12.** GET выполняется к `/` на внешнем baseURL. Второй аргумент является конфигурацией, а не телом запроса. Instance и перехватчики остаются общими.
- **Строка 13.** `null` и пустой массив снова нормализуются в `[]`, чтобы хук одинаково обрабатывал пустоту обоих источников.
- **Строка 14.** Проверяется строковый тип `quote`. Неожиданный JSON превращается в явную ошибку, а не в загадочную пустую карточку.
- **Строка 15.** Пустая после удаления краевых пробелов цитата означает пустой успешный результат.
- **Строка 16.** Цитата преобразуется в общий объект `{ id, text }` внутри массива. UI не должен знать, что у внешнего API поле называлось `quote`.

### Строки 9-15. Обработчик и ранние проверки

**Что делает блок и зачем:** Создаёт JSON-ответы и проверяет метод, ключ и происхождение.

```javascript
export async function handleOwl(request, env) {
  const reply = (data, status = 200) => Response.json(data, { status, headers: { 'Cache-Control': 'no-store' } })
  if (request.method !== 'POST') return reply({ error: 'Нужен POST-запрос.' }, 405)
  if (!env.GEMINI_API_KEY) return reply({ error: 'Сова пока не готова отвечать. Загляни чуть позже.' }, 503)
  const origin = request.headers.get('Origin')
  if (origin && origin !== new URL(request.url).origin) return reply({ error: 'Запрос с другого сайта отклонён.' }, 403)

```

**Построчно:**

- **Строка 9.** Экспортируется асинхронный handleOwl с Web Request и объектом окружения env. Возвращаемый Promise разрешается в Response.
- **Строка 10.** Локальная функция reply создаёт JSON Response со статусом по умолчанию 200 и Cache-Control:no-store. Параметр status можно переопределить для ошибки.
- **Строка 11.** Если метод не POST, сразу возвращается JSON с 405. Дальнейшие проверки и внешний запрос не выполняются.
- **Строка 12.** При отсутствии секретного ключа возвращается 503 и сообщение о временной неготовности. Значение ключа нигде не подставляется в текст ошибки.
- **Строка 13.** Из входящих заголовков читается Origin. Значение может отсутствовать, поэтому проверка ниже условная.
- **Строка 14.** Если присутствующий Origin отличается от origin самого URL, возвращается 403. Сравниваются схема, хост и порт; это не полноценная аутентификация запросов.
- **Строка 15.** Пустая строка отделяет ранние проверки от блока обработки тела.


### Строки 7-15. Обход dist

**Что делает блок и зачем:** Собирает только нужные клиентские ресурсы.

```javascript
async function collect(directory) {
  for (const entry of await readdir(directory, { withFileTypes: true })) {
    if (entry.name === 'server' || entry.name === '.openai') continue
    const path = `${directory}/${entry.name}`
    if (entry.isDirectory()) await collect(path)
    else assets[path.slice(4)] = { type: types[path.slice(path.lastIndexOf('.'))] || 'application/octet-stream', body: (await readFile(path)).toString('base64') }
  }
}

```

**Построчно:**

- **Строка 7.** Объявляется асинхронная collect с путём каталога.
- **Строка 8.** Читаются записи каталога с withFileTypes. For of обходит записи, а сведения Dirent позволяют отличить папку от файла.
- **Строка 9.** Имена server и .openai пропускаются, чтобы не упаковать сгенерированный Worker сам в себя и не раздать служебную конфигурацию как статику.
- **Строка 10.** Path собирает путь текущей записи через шаблонную строку.
- **Строка 11.** Каталог рекурсивно обходится с await collect, пока не будут прочитаны вложенные ресурсы.
- **Строка 12.** Для файла path.slice(4) убирает dist, оставляя URL со слешем. Расширение определяет MIME; readFile получает байты и toString(base64) превращает их в строку для встраивания.
- **Строка 13.** Закрывается цикл обхода.
- **Строка 14.** Закрывается collect.
- **Строка 15.** Пустая строка отделяет определение от запуска.

### Строки 21-32. Выполнение будущего Worker

**Что делает блок и зачем:** Это текст генерируемой программы, который запустится после публикации.

```javascript
  async fetch(request, env) {
    const path = new URL(request.url).pathname;
    if (path === '/api/owl') return handleOwl(request, env);
    if (path === '/api/saved') return handleSaved(request, env);
    if (path.startsWith('/api/')) return Response.json({ error: 'Маршрут не найден.' }, { status: 404 });
    const asset = assets[path] || (!path.split('/').pop().includes('.') ? assets['/index.html'] : undefined);
    if (!asset) return new Response('Не найдено', { status: 404 });
    const body = request.method === 'HEAD' ? null : Uint8Array.from(atob(asset.body), char => char.charCodeAt(0));
    return new Response(body, { headers: { 'Content-Type': asset.type, 'Cache-Control': 'no-cache' } });
  }
};`
await mkdir('dist/server', { recursive: true })
```

**Построчно:**

- **Строка 21.** Объявляется async fetch будущего Worker с Request и env. Платформа вызовет его при HTTP-запросе после публикации.
- **Строка 22.** Из входящего URL берётся pathname. Query-параметры не меняют поиск маршрута или ресурса.
- **Строка 23.** Точный /api/owl передаётся общему обработчику совы. Возвращается его Promise Response.
- **Строка 24.** Точный /api/saved передаётся обработчику копилки с тем же env, где хостинг предоставляет DB.
- **Строка 25.** Любой оставшийся путь с /api/ получает JSON 404. Он не должен случайно стать HTML-страницей React.
- **Строка 26.** Сначала ищется реальный asset по пути. Если его нет и последний сегмент не содержит точку, выбирается index.html: это простой SPA fallback для прямых ссылок страниц.
- **Строка 27.** При отсутствии подходящего ресурса возвращается 404. Например, отсутствующий .js не подменяется HTML.
- **Строка 28.** Для HEAD тело null. Иначе atob декодирует base64, затем Uint8Array.from превращает двоичные символы в исходные байты через charCodeAt(0).
- **Строка 29.** Создаётся Response статического файла с MIME и Cache-Control:no-cache. Это требует проверки актуальности HTTP-кеша, а не запрещает JavaScript-кеш TanStack Query.

- **Строка 31.** Закрывается default-объект Worker и обратной кавычкой завершается многострочная строка. Всё внутри неё станет JS в выходном файле.

### Два времени одного файла

Collect, readFile и writeFile выполняются во время сборки в Node. Строки внутри worker являются текстом будущей программы. Подстановки handler и JSON.stringify(assets) выполняются сейчас, а метод fetch из полученной строки позднее вызовет платформа Worker. Большая таблица assets в dist получается автоматически и не является вручную написанным JSON приложения.

## Финальная проверка понимания

Проследи пять цепочек без пропусков:

1. Select -> setSource -> store -> фильтрация на обеих страницах.
2. Submit -> submittedQuestion -> queryKey -> queryFn -> Axios -> ответ -> кеш -> карточка.
3. Нажатие сохранения -> mutate -> POST -> проверка -> SHA-256 -> SQL -> onSuccess -> invalidateQueries.
4. NavLink -> BrowserRouter -> Routes -> страница; отдельно прямой URL -> Worker -> index.html -> Router.
5. Команда build -> Vite dist -> collect -> строка Worker -> запись выходного файла -> публикация.

Если умеешь отличить в этих цепочках локальное состояние, общий store, кеш и постоянную серверную базу, основная идея шестой лабораторной понятна. Если можешь объяснить только синтаксис одной стрелочной функции, вернись к общему пути данных в первом гайде.

Номера актуальны для этого снимка. После будущего изменения исходников сравни соответствующий блок с реальным файлом. Полнота документа относится к перечисленным собственным файлам, а не ко всем внутренностям React, Vite, Axios и других зависимостей.
