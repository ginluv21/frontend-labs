# Сова на скакалке

Учебный React-проект в стиле 2000-х. Лабораторная 6 продолжает лабораторную 5.

## Что работает

- `/` - вопрос сове, ответ по смыслу и случайная цитата Канье.
- `/saved` - общая копилка сохранённых советов.
- Один фильтр: все, сова или Канье. Выбор сохраняется при переходах между страницами.
- У каждого ответа кнопка «В копилку». Во время сохранения она заблокирована.
- Загрузка, ошибка, повтор и пустой результат обрабатываются отдельно.
- Неизвестный адрес показывает страницу с предложением вернуться на главную.

Копилка общая для посетителей сайта, без аккаунтов. Реализованы просмотр и добавление.
Повторное сохранение того же текста от того же источника не создаёт дубликат.

## Запуск

Нужен Node.js 24. Локальная копилка использует встроенный `node:sqlite`.

```bash
npm install
npm run dev
```

Для ответа совы локально нужен `.env.local` с серверной переменной `GEMINI_API_KEY`.
Необязательная переменная `GEMINI_MODEL` выбирает модель.
Ключ не должен иметь префикс `VITE_` и не должен попадать в Git.
На хостинге он хранится в секретах среды. Без ключа сова показывает ошибку,
остальные функции работают независимо.

Локальная база автоматически создаётся в `.data/saved.sqlite`. Эта папка игнорируется Git.
База локального сайта и опубликованного сайта отдельные.

```bash
npm run build
npm run preview
```

Сборка создаёт клиент и Worker в `dist`. Preview показывает сборку с локальным API.
Публикация является отдельным действием.

## Состояние и запросы

Zustand хранит только `source`: `all`, `owl` или `kanye`.
Store создан вне компонентов, при рендере не пересоздаётся.
Его используют `SourceFilter`, `AdvicePage` и `SavedPage`.
После полной перезагрузки фильтр сбрасывается, как допускает задание.

Все браузерные API-запросы выполняются функциями TanStack Query через общий Axios instance.
Прямых сетевых запросов из эффектов компонентов нет. Эффект таймера совы сохранён.
Ответы API не копируются в Zustand или отдельный React-state.
Текст поля и последний отправленный вопрос являются локальным состоянием формы.

Queries:

- `['advice', 'owl', question]` - ответ совы по конкретному вопросу.
- `['advice', 'kanye']` - случайная цитата.
- `['saved']` - список копилки.

`staleTime` равен 60 секундам. Пока данные свежие, возврат на страницу использует кеш.
По умолчанию неактивный кеш удаляется TanStack Query через 5 минут.
Автоматический повтор при ошибке и обновление при фокусе окна отключены.
Ручной повтор делает новый запрос. Повтор совы использует отправленный вопрос,
а не изменённый без отправки черновик. Повторная отправка того же вопроса обновляет ответы.
Возврат к другому ранее заданному вопросу может использовать его свежий кеш.
Канье не анализирует вопрос, он возвращает случайную английскую цитату.

Mutation `saveAdvice` выполняет POST с источником и текстом.
При успехе вызывается `invalidateQueries({ queryKey: ['saved'] })`.
Активный список обновится; неактивный будет помечен устаревшим и загрузится при открытии.
Ожидание и ошибка mutation видны рядом с кнопкой, повтор до завершения заблокирован.

## Сервер копилки

Один маршрут `/api/saved`:

- GET возвращает массив `{ id, source, text }`.
- POST проверяет источник и непустой текст до 4000 символов, затем сохраняет запись.

На хостинге используется D1 с привязкой `DB`, локально SQLite.
Схема находится в `drizzle/0000_saved_advice.sql`, журнал миграций в `drizzle/meta/_journal.json`.
Таблица создаётся при настройке базы, а не внутри обработчика запросов.
SQL использует параметры. Идентификатор вычисляется из источника и текста через SHA-256,
поэтому одинаковый совет не создаёт две записи при повторной отправке.
Всего в записи три поля, дополнительных сущностей нет.

`/api/owl` работает как в лабораторной 5: сервер добавляет инструкцию персонажа,
обращается к внешней модели через fetch и возвращает `{ advice }`.
Серверный fetch не относится к браузерным запросам TanStack Query.
Секретный ключ не передаётся React.

Worker отдаёт index.html для адресов страниц, поэтому прямое открытие `/saved`
и обновление этой страницы работают. Неизвестный API и отсутствующий файл получают 404.
Неизвестный адрес страницы обрабатывает React Router.

## Где что находится

- `src/main.jsx` - BrowserRouter и QueryClientProvider.
- `src/App.jsx` - общая шапка, навигация, фильтр, маршруты и подвал.
- `src/pages/AdvicePage.jsx` - вопрос и карточки источников.
- `src/pages/SavedPage.jsx` - запрос копилки и фильтрация списка.
- `src/store/useFilter.js` - единственное общее клиентское состояние.
- `src/api/queryClient.js` - один QueryClient и настройки кеша.
- `src/api/client.js` - общий Axios, адреса, таймаут и перехватчики.
- `src/api/advice.js`, `src/api/saved.js` - HTTP-функции.
- `src/hooks/useAdvice.js` - query-хуки двух источников и повтор.
- `src/components/SaveButton.jsx` - mutation и инвалидация копилки.
- `src/components/SourceFilter.jsx` - изменение фильтра Zustand.
- `server/saved.js` - серверный маршрут копилки.
- `server/local-db.js` - локальная база с интерфейсом для общего обработчика.
- `vite.config.js` - React, alias `@`, локальные API-маршруты.
- `scripts/build-server.mjs` - сборка Worker и статики для хостинга.

## Как показать шестую лабораторную

1. Открыть главную: оба источника загружаются автоматически.
2. Выбрать «Только сову»: карточка Канье скрывается.
3. Сохранить совет: видны ожидание и заблокированная кнопка.
4. Перейти через ссылку в копилку: совет появился, фильтр остался.
5. Переключить фильтр, перейти назад и вперёд: страницы согласованно показывают выбор.
6. Быстро вернуться в копилку: свежий список используется без нового GET.
7. Сохранить новый совет и открыть копилку: после инвалидации выполняется новый GET.
8. Заблокировать POST `/api/saved` в DevTools: видна ошибка сохранения.
   Снять блокировку, нажать кнопку ещё раз: сохранение успешно.
9. Для ошибки чтения заблокировать GET копилки и обновить страницу.
   Снять блокировку и нажать «Повторить».
10. Для пустоты подменить успешный GET копилки на `[]` через Local Overrides.
    После демонстрации убрать подмену и блокировки.
11. Открыть `/saved` напрямую, проверить обновление страницы и неизвестный путь.
12. Показать в Network HTTP-запросы и в Console логирование Axios.

Проверки не требуют удаления реальных записей. Для первоначально пустой копилки
подойдёт новая локальная база или подмена ответа в DevTools.
